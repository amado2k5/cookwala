أمثلة برمجية لكل دور، بأربع لغات

عملاء ووكلاء ومنسّقون وبوابات واستعادة وتقارير لواجهة النواة 0.2، بلغات بايثون وجافاسكربت وجافا وC#. تعمل دون اتصال على أجهزة محاكاة، أو مع أي موزّع كوكوالا. وكل نسخة تختبر نفسها مقابل التنفيذ المرجعي.

شغّل العرضاحصل على الحزمدليل الأمثلة (بالإنجليزية)المصدر على GitHub

هذه أمثلة، وليست برمجيات معتمدة. الجهاز المنفِّذ هو صاحب القرار دائمًا: تفحص البوابات مبكرًا ليشرح العميل سبب الرفض، ثم يفحص الجهاز كل شيء من جديد. منشورة على PyPI وnpm وNuGet وMaven Central وHomebrew، والملف الواحد وحزمة .deb على إصدارات GitHub؛ وكل بطاقة أدناه تبيّن إن كانت قناتها متاحة بعد (الحالة لكل قناة).

جرّبها: دقيقة واحدة، دون تثبيت

  1. شغّل ستة طلبات على مطبخ محاكى من أربعة أجهزة. بايثون بمكتباتها القياسية فقط، لا شيء للتثبيت.

    git clone https://github.com/amado2k5/cookwala && cd cookwala/samples/python
python -m cookwala_samples demo
    6 runs: 3 completed, 1 failed, 1 refused, 1 stopped. Served 3, discarded 2, incidents reported 2, people asked 3 times.

  2. أو ثبّتها من أحد السجلات. الأمر نفسه في كل لغة؛ والأمر help يشرح كل أمر مع أمثلة.

    pip install cookwala-samples        # أو: npm i -g @cookwala/samples · dotnet tool install -g Cookwala.Samples.Tool
cookwala-samples demo
cookwala-samples help run

  3. اسأل البوابات عن وصفة واحدة على جهاز واحد.

    python -m cookwala_samples gates koshari --device demo-hob-robot-basic --human-present
    "refusal": {"reason": "missing_sensor_no_fallback", "detail": "no way to verify cw.op.deep_fry on this device", "gate": "capability", "node": "n14"}

  4. اكسر شيئًا عمدًا وراقب الاستعادة.

    python -m cookwala_samples run koshari --human-present --fault 'example-koshari#n14=overheat' --format csv
    1-koshari,example-koshari,demo-hob-robot,stopped,,discard_and_report,discard,0,cw.incident.overheat

  5. وجّهها إلى موزّع حقيقي. الشيفرة نفسها عبر HTTP.

    cookwala hub --port 7878 &
python -m cookwala_samples demo --hub http://localhost:7878

الأدوار الستة

العملاء

واجهة واحدة عبر HTTP وعبر منفِّذ محاكى. إعادة المحاولة تستخدم مفتاح التكرار نفسه، فلا يُطهى طلب مرتين؛ وأمر الإيقاف يُعاد حتى يصل.

الوكلاء

وكيل تخطيط يعمل بتفويض موقَّع: صلاحيات وانتهاء وقائمة ما يحتاج تأكيدًا. لا يلتفّ أبدًا على حظر مسبِّب للحساسية، ويسأل شخصًا قبل أي فعل لا رجعة فيه. ووكيل مراقبة يفحص كل انتقال في الحالة وكل درجة حرارة.

المنسّقون

البوابات أولًا، ثم تجربة جافة على كل جهاز. يفوز الجهاز الذي يحتاج أقل عدد من الناس. ثم البدء والمتابعة والاستعادة وجمع السجل والتقرير. وجودها اختياري بالتصميم: كوكوالا تعمل دونها.

البوابات

إصدار النواة، وبصمة الوصفة، والاستدعاء، والتفويض، ومسبِّبات الحساسية، والنص غير الموثوق، والنطاق والحدود المحلية، والحضور، وقدرة الجهاز. أول رفض يوقف الطلب، والبوابة التي تتعطّل ترفض.

الاستعادة

لا إعادة محاولة تلتفّ على السلامة أبدًا. الجهاز المشغول أو غير القادر يُحيل الطلب إلى التالي. يُسأل شخص عند الحاجة، وإن لم يُجب أحد يتوقف الطهي. وبعد بدء التسخين، يعني الفشل التخلّص من الطعام والإبلاغ.

التقارير

سجل لكل تشغيل وملخّص، بصيغ JSON وMarkdown وJUnit XML للوحات التكامل المستمر وCSV. تقارير الحوادث مجهولة الهوية: تاريخ فقط، بلا أسماء، ومعرِّف عشوائي.

احصل على الحزم

حمولة واحدة لأنظمة التشغيل: نسخة بايثون بلا اعتماديات، فملف واحد يعمل على أي بايثون 3.9 أو أحدث، وكل مدير حزم يشحن هذا الملف. وسجلات اللغات تشحن النسخة الأصلية لكل لغة. كل بطاقة تشير إلى ملف الحزمة في المستودع.

الشيفرة نفسها كخدمة

الأمر cookwala-samples serve وصورة الحاوية وكل دالة سحابية تستدعي معالجًا واحدًا:

النقطةالجواب
GET /healthالحياة والإصدار
POST /v1/samples/gatesقرار البوابات لوصفة وجهاز وحظر وتفويض
POST /v1/samples/planطلب وكيل التخطيط وترتيب الأجهزة
POST /v1/samples/runمهام منسَّقة مع أعطال محقونة، في تقرير
GET /v1/samples/demo?format=تقرير العرض: json وmarkdown وjunit وcsv

لا تتحدث الخدمة إلا مع أجهزتها المحاكاة، ولا تتصل بأي مضيف آخر، فلا يمكن استخدام دالة عامة للوصول إلى مطبخ أحد.

صادقة بالاختبارات

  • كل نسخة تفحص JSON القانوني وبصمات الوصفات و32 تجربة جافة مقابل إجابات حسبتها المكتبة المرجعية (samples/data/bundle.json).
  • اختبارات بايثون تقارن التجربة الجافة مع tools/cookwala_ref.py لكل وصفة وجهاز في الأمثلة، وتتحقق من كل طلب وحالة وسجل وحادثة مقابل مخططات JSON.
  • كل نسخة تشغّل العرض مع الموزّع المرجعي عبر HTTP.
  • التكامل المستمر يثبّت حزمة .deb، ويشغّل الحاوية بمستخدم عشوائي على نظام ملفات للقراءة فقط، ويفحص مخطط Helm.
  • نشر Azure Functions مُثبت على اشتراك حقيقي: مهمة تعمل عند الطلب تبني حزمة Bicep، وتنشر الدالة، وتتحقق من /health و/v1/samples/plan وتقرير العرض عبر الرابط العام، ثم تحذف مجموعة الموارد.
