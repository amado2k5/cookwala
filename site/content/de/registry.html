Ein Registry hält Pointer, keinen Inhalt: was existiert, wer es veröffentlicht hat, welche exakte Version und dessen Hash. Namen werden durch DNS oder ein Code-Host-Konto nachgewiesen; Versionen sind exakt; zurückgezogene Einträge bleiben als Tombstones bestehen. Jeder darf ein Registry betreiben. Dieses hier listet nur auf, was heute im Repository existiert, und sagt dies auch so.

Veröffentlichen

  1. Validate locally with the same checks the registry runs.

    cookwala validate
cookwala hash my-collection/recipe.cookwala.json

  2. Prove your namespace once: a DNS TXT record cookwala-verify=<token> on your domain, a /.well-known/cookwala-verify file, or a GitHub or GitLab OIDC token from a CI job in your account.

  3. Publish the entry.

    curl -X POST https://cookwala.ai/v1/registry/publish \
  -H "Authorization: Bearer $COOKWALA_PUBLISH_TOKEN" -H "Content-Type: application/json" -d @entry.json

    next The publish and validate endpoints are specified (registry.openapi.yaml) and come with the registry service. Today entries are added by pull request to site/v1/registry.json.

Regeln

  • Namen: <reverse-dns-namespace>/<name>, Kleinschreibung, 3 bis 200 Zeichen.
  • Versionen exakt (1.4.2); Bereiche und latest abgelehnt.
  • Jede Version zeichnet das sha256 ihres Artefakts auf; Rezepte tragen zudem ihren eigenen Dokumenten-Hash.
  • Lebenszyklus: active → deprecated → recalled (auch im recall feed) → deleted (tombstone). Namen werden niemals wiederverwendet.
