Encontre e publique, sob nomes que comprovem quem publicou

Um registry contém ponteiros, não conteúdo: o que existe, quem publicou, qual versão exata e seu hash. Os nomes são comprovados por DNS ou uma conta de host de código; as versões são exatas; entradas retiradas permanecem como tombstones. Qualquer pessoa pode executar um registry. Este lista apenas o que existe no repositório hoje, e diz isso.

Publicar

  1. Validate locally with the same checks the registry runs.

    cookwala validate
cookwala hash my-collection/recipe.cookwala.json

  2. Prove your namespace once: a DNS TXT record cookwala-verify=<token> on your domain, a /.well-known/cookwala-verify file, or a GitHub or GitLab OIDC token from a CI job in your account.

  3. Publish the entry.

    curl -X POST https://cookwala.ai/v1/registry/publish \
  -H "Authorization: Bearer $COOKWALA_PUBLISH_TOKEN" -H "Content-Type: application/json" -d @entry.json

    next The publish and validate endpoints are specified (registry.openapi.yaml) and come with the registry service. Today entries are added by pull request to site/v1/registry.json.

Regras

  • Nomes: <reverse-dns-namespace>/<name>, letras minúsculas, de 3 a 200 caracteres.
  • Versões exatas (1.4.2); intervalos e latest rejeitados.
  • Cada versão registra o sha256 de seu artefato; as receitas também carregam seu próprio hash de documento.
  • Ciclo de vida: active → deprecated → recalled (também no feed de recall) → deleted (tombstone). Nomes nunca são reutilizados.
