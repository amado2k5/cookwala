# Cookwala Core 0.2

**Status:** draft, 2026-10-04. Это нормативная часть Cookwala. MUST, SHOULD и MAY
соответствуют RFC 2119. Все, что не перечислено здесь, является необязательным **profile** (раздел 10).

Устройство должно иметь возможность реализовать Core примерно за неделю. Core говорит, **что готовить, когда это готово и чего никогда не должно происходить**. Он не говорит, как перемещается робот.

## 1. Классы conformance

| Класс | Должен реализовывать |
|---|---|
| **Recipe publisher** | Валидные документы `recipe.schema.json`; температуры внутри operation envelopes; хеш и подпись |
| **Executor** (робот, бытовой прибор или hub) | Core API (`api/core.openapi.yaml`); operation envelopes и sensor ladders; локальные пределы безопасности; refusal вместо догадок; execution log |
| **Catalog** | Подписанные рецепты, `/.well-known/cookwala.json` с ключевыми записями, лента recall, прием инцидентов |
| **Agent** (ИИ или ПО, действующее от имени человека) | Действует только на основании `AgentMandate`; обрабатывает текст документа как данные; запрашивает разрешение у принципала перед любым действием в `confirmBefore` |
| **Verifier** | Хеши, подписи, валидность и отзыв ключей, раскрытия, цепочки событий и контрольные точки |

Заявление класса означает прохождение его векторов conformance (`conformance/`, запуск с
`tools/run_conformance.py`).

## 2. Основные документы

| Документ | Схема |
|---|---|
| Recipe | `recipe.schema.json` |
| Device capabilities | `capabilities.schema.json` |
| ExecuteRequest, ExecutionStatus, StopRequest, ExecutionLog | `core.schema.json` |
| SafetyLimits, Recall, IncidentReport, ConformanceVector | `core.schema.json` |
| Shared types (Quantity, Condition, Money, Signature, KeyRecord, Disclosure, AgentMandate) | `common.schema.json` |
| Events | `event.schema.json` (CloudEvents) |
| Vocabularies: operations, units and heat levels, incidents | `vocab/*.json` |

Все схемы являются **строгими**: неизвестные поля отклоняются, за исключением расширений `x-<vendor>-…`.
Читатели игнорируют поля `x-`, которые они не понимают. `tools/bundle_schemas.py` создает единый
бандл, чтобы устройства могли выполнять валидацию офлайн. Реализации НЕ ДОЛЖНЫ загружать схемы во время выполнения.

## 3. Что означают операции

- **Envelopes.** Каждая операция на основе нагрева или опасная операция в `vocab/ops.json` имеет `envelope`.
  Она определяет:
  - среду (вода, масло, воздух, поверхность сковороды, продукт…);
  - её температурный диапазон в °C (и давление, для приготовления под давлением);
  - перемешивание, крышку, уровень внимания и может ли шаг выполняться без присмотра;
  - опасности;
  - метод тестирования.

`cw.op.simmer` = water-based liquid at 85–96 °C; `cw.op.deep_fry` = oil at 160–190 °C.
- **Targets inside envelopes.** Целевой показатель рецепта (`params.tempC` или `target` на сенсоре среды) ДОЛЖЕН находиться внутри envelope. Валидатор отклоняет рецепты, которые нарушают это правило.
- **Executors keep the medium inside the envelope.** Если рецепт задает более узкий target, исполнители также удерживают среду внутри него после того, как он будет впервые достигнут.
- **Altitude.** Диапазоны воды и пара смещаются на −1 °C на каждые 300 m высоты кухни.
- **Heat levels** (`very_low` … `max`) имеют одно общее значение: диапазон температуры поверхности сковороды в °C, определенный в `vocab/units.json`.
- **Sensor ladder.** Каждый envelope перечисляет способы проверки шага, в лучшем порядке: конкретный сенсор, затем `model` (зафиксированная оценка), затем `time`, затем `human`.
  - Исполнитель использует первую ступень, которую он может выполнить, и записывает её в `verifiedBy`.
  - Если он не может выполнить **ни одну** ступень, он ДОЛЖЕН отклонить шаг (`missing_sensor_no_fallback`).
  - Операции, требующие постоянного внимания и которые нельзя оставлять без присмотра (обжаривание, запечатывание, жарка, выпаривание, карамелизация…), никогда не переходят только на `time`: их последняя ступень — это человек, наблюдающий за процессом.
  - Deep frying не имеет fallback: отсутствие сенсора температуры масла означает отсутствие deep frying.
  - `Condition` может сузить это с помощью `onSensorMissing`.
- **Refusal, not guessing.** Исполнитель, который не может соответствовать envelope, ladder, оборудованию или ограничениям безопасности шага, ДОЛЖЕН ответить `refused` с указанием причины перед началом.

## 4. Numbers and units

- **Температуры указаны в °C в wire.** Дисплеи могут конвертировать.
- **Допуски.**
  - `tolerance` является относительным и допускается только для единиц шкалы отношений.
  - `toleranceAbs` является абсолютным в единицах значения, и это единственный допустимый допуск для °C.
  - `Target.tolerance` является абсолютным.
- **Кухонные единицы имеют точные метрические значения:** tsp 5 ml, tbsp 15 ml, cup 240 ml,
  pinch ≈ 0.36 g, dash ≈ 0.6 ml.
- **Для связи Объем ↔ масса требуется плотность** (`Quantity.densityGPerMl` или словарь ингредиентов);
  без неё это ошибка, а не предположение.
- **Деньги — это десятичная строка** (`"12.70"`) с валютой ISO 4217, а не float.

## 5. Целостность и доверие

- **Hash.** `sha256:` плюс hex-дайджест канонического JSON документа согласно RFC 8785,
  без полей `hash` и `signature`. Ссылочный канонизатор в точности воспроизводит пример
  RFC 8785.
- **Signature.** Ed25519 (`EdDSA`) поверх ASCII-строки хеша. `ES256` допускается для аппаратных
  ключей P-256. `kid` называет `KeyRecord`.
- **Keys.** `KeyRecord` предоставляет публичный ключ, его владельца, окно валидности и `revokedAt`.
  Подпись, чей `signedAt` наступает после отзыва или вне окна валидности, является
  недействительной.
  - Каталоги публикуют свои ключи в `/.well-known/cookwala.json`.
  - Организации и люди публикуют свои в документах did:web.
  - Устройства публикуют свои в своем документе возможностей.
  - Верификаторы кэшируют записи ключей для офлайн-использования.
- **Selective disclosure.** Подписанный документ может содержать дайджест `Disclosure`,
  `sha256(JCS([salt, value]))`, вместо конфиденциального значения. Держатель раскрывает salt и
  value только сторонам, которым разрешено их видеть, и подпись по-прежнему проходит проверку.
- **Event logs** (Mission profile):
  - Один секвенсор на каждый лог назначает `seq` и `prev`, чтобы цепочка никогда не разветвлялась.
  - Контрольные точки подписываются секвенсором и заверяются свидетелями, которыми могут быть
    сервисы прозрачности, такие как IETF SCITT. Перезапись после заверенной контрольной точки
    обнаруживаема.
  - В режиме `hash_only` полезная нагрузка хранится в стираемом хранилище, а лог хранит только их хеши.

## 6. Правила безопасности и правила агента (нормативные)

1. **Безопасность локальна.** Исполнители применяют пакет `SafetyLimits` на устройстве.
   - Никакой рецепт, агент, удаленное сообщение, расширение или режим работы не могут повысить или отключить лимит.
   - Более строгий лимит всегда имеет приоритет.
   - `profiles/core/safety-limits.default.json` является черновым отправным пунктом, который производители устройств
     ужесточают на основе своего собственного обоснования безопасности.
2. **Локальная остановка.** Контроль остановки на устройстве прекращает движение в течение 0.5 s и отключает нагрев в течение
   1 s, с сетью или без нее. `POST …/stop` никогда не отклоняется по причине авторизации, как только
   вызывающий может связаться с исполнителем.
3. **События сообщают; они никогда не защищают.** События `cookwalalatency: local_safety` сообщают о том, что
   устройство уже сделало. Ни одна функция безопасности не может зависеть от прибытия события.
4. **Недоверенный текст.** Каждое поле произвольного текста (аннотированное `x-cookwala-untrusted`) является данными и никогда не
   является инструкцией, как для программного обеспечения, так и для AI агентов. Попытки дать инструкцию через текст
   игнорируются и записываются в лог (`cw.incident.untrusted_instruction`).
5. **Агенты действуют на основании мандата.** Запрос, отправленный агентом, несет в себе `AgentMandate`, подписанный
   принципалом: области действия, лимиты расходов, разрешенные поставщики, срок действия и действия, требующие
   подтверждения.
   - `irreversible` и `safety_override` всегда требуют подтверждения, что бы ни говорил мандат.
   - Исполнители отклоняют запросы вне мандата (`mandate_scope`).
6. **Неконтролируемые операции требуют участия человека.** Операции, чей envelope указывает `unattended: false`,
   требуют присутствия ответственного лица или возможности связаться с ним в течение одной минуты.
7. **Блокировка аллергенов отклоняет.** Любой заблокированный аллерген в рецепте или в инвентаре отклоняет
   запрос; обход блокировки через замены невозможен.
8. **Отзывы.** Каталоги публикуют подписанные recalls по адресу `GET /v1/recalls`. Исполнители опрашивают их, когда находятся в сети,
   и отклоняют отозванные ревизии. `block_and_stop_running` также безопасно останавливает выполняющиеся executions.
9. **Отчеты об инцидентах** являются анонимными (`IncidentReport`: только дата, без имен или ids) и
   отправляются в каталоги, чтобы каждый производитель мог извлечь урок из каждого случая, едва не приведшего к происшествию.

## 7. Жизненный цикл выполнения и API

- **API:** `api/core.openapi.yaml`. Его эндпоинты:
  - `POST /v1/executions`, `GET /v1/executions/{id}`;
  - `POST /v1/executions/{id}/stop`, `POST /v1/executions/{id}/resume`, `GET /v1/executions/{id}/log`;
  - `GET /v1/safety-limits`, `GET /v1/capabilities`;
  - со стороны каталога: `GET /v1/recalls`, `POST /v1/incidents`.
- **Состояния:**
  - `accepted` → `preparing` → `running` → `completed`;
  - `paused`, `needs_human` и `stopping` → `stopped` в процессе;
  - `refused` и `failed` являются финальными.
  - Полная таблица переходов находится в `core.schema.json#/$defs/ExecutionState` и
    векторах conformance.
- **Правила запросов:**
  - Каждый POST несет `Idempotency-Key`.
  - Изменения существующего execution несут `If-Match: <seq>`; несоответствие возвращает 412.
  - Stop не требует If-Match.
- **События:**
  - Доставка осуществляется как минимум один раз.
  - CloudEvents `id` является ключом дедупликации.
  - `cookwalaseq` упорядочивает события по subject и соответствует статусу `seq`.
  - Устройства излучают `cookwala.device.heartbeat`, поэтому hub может обнаружить потерянное устройство и передать управление.

## 8. Конфиденциальность

- **Execution logs не содержат персональных данных** (`privacy.personalData: "none"`).
- **Они покидают устройство только при наличии согласия opt-in** (`consent.dataset`: `none` по умолчанию,
  `research_only` или `open`). Согласие может быть отозвано.
- **Открытые наборы данных округляют время до дня.**
- **Данные о household, здоровье и религии остаются дома**, если человек не решит иначе.
  Когда они должны передаваться, они передаются как selective disclosures.
- **The Humanitarian Profile** вообще не содержит персональных данных.

## 9. Версионирование и расширения

- **Основные версии — `0.2.x`.**
  - Читатели принимают любой патч своей минорной версии.
  - Они отклоняют другие минорные версии с `unsupported_version`.
  - Они игнорируют неизвестные поля `x-`.
- **Новые операции, единицы измерения, сенсоры и типы инцидентов** добавляются в словари без
  изменения версии.
- **Изменение значения операции — это новый id;** старый помечается как `deprecated` с
  `replacedBy`.
- **Профили** версионируются независимо и заявляют версию Core, которая им необходима.

и у него есть реальные пользователи.

## 12. Изменения с версии 0.1

| Область | 0.1 | 0.2 |
|---|---|---|
| Schemas | Приняты неизвестные поля | Строгие, с расширениями `x-` |
| Temperatures | °C или °F, допускается относительная погрешность | Только °C; абсолютная погрешность |
| Money | Число | Десятичная строка |
| Operations | Прозаичные определения | Физические operation envelope, sensor ladder, уровни тепла, тестовые векторы |
| Signatures | Фиксированные EdDSA, ключи без жизненного цикла | EdDSA или ES256, KeyRecords с валидностью и отзывом |
| Missions | Один изменяемый документ, ledger внутри | Event log + проекция, единый секвенсор, подтвержденные контрольные точки, режим только с хешами |
| Agents | Mandate только внутри Missions | `AgentMandate` в общем доступе; требуется для запросов агентов |
| Safety | Объявлено в рецептах | Также обеспечивается локально через SafetyLimits; recalls; отчеты об инцидентах |
| Data | Без модели набора данных | ExecutionLog с согласия, без персональных данных |
| Conformance | Только валидация схем | 106 векторов (44 Core, 62 profile) плюс эталонная реализация |

Для миграции документа 0.1: преобразуйте °F в °C; замените относительные допуски для температур на `toleranceAbs`; преобразуйте денежные суммы в десятичные строки; удалите или переименуйте неизвестные поля в поля `x-`.
