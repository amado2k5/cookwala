# Cookwala Recipe Format: συνταγές που λειτουργούν με Missions

Μια συνταγή στο Cookwala δεν είναι μια λίστα οδηγιών. Είναι **φορητή γνώση μαγειρέματος**
που ένας σχεδιαστής *συνθέτει* σε σχέση με μια συγκεκριμένη Αποστολή (household, robots, appliances,
energy, budget, health, timing) σε ένα εκτελέσιμο σχέδιο. Στη συνέχεια ο ρομπότ εκτελεί αυτό το σχέδιο,
προσαρμοζόμενο μέσω περιπτώσεων έκτακτης ανάγκης και playbooks όταν η πραγματικότητα αλλάζει.

Schema: [`recipe.schema.json`](../schemas/recipe.schema.json). Πλήρες παραδείγμα:
[`examples/shakshuka.cookwala.json`](../examples/shakshuka.cookwala.json).

## 1. Τέσσερα επίπεδα (προσαρμοσμένα από την προσέγγιση των WHO SMART Guidelines)

| Επίπεδο | Τι περιέχει | Ποιος το γράφει | Πού βρίσκεται |
|---|---|---|---|
| **R1 Narrative** | Κείμενο συνταγής από ανθρώπους, ιστορία, πολιτισμικές σημειώσεις, φωτογραφίες | Cook, σεφ, fifi.cooking | `text`, `dish.images` |
| **R2 Dish spec** | Τι *είναι* και τι *πρέπει να είναι* το πιάτο: ταυτότητα (απαραίτητη vs ευέλικτη), αισθητηριακοί στόχοι, θρεπτικά στοιχεία, στυλ σερβιρίσματος και κατανάλωσης, αποθήκευση, έλεγχοι αποδοχής | Συντάκτες συνταγών, με βοήθεια AI, ελεγχόμενα | `identity`, `sensory`, `service`, `storage`, `nutrition`, `acceptance` |
| **R3 Executable IR** | Μέθοδος ανεξάρτητη από συσκευή:สูตร (αναλογίες + ρόλοι), γράφημα διαδικασίας με τύπους ops με προ/μετά συνθήκες κατάστασης τροφίμων, συνθήκες `until`, εναλλακτικές, κανόνες παύσης, τρόποι αποτυχίας, affordances, κίνδυνοι, CCPs, προετοιμασία περιβάλλοντος | Export pipeline + review; simulator-verified (V2) | `formula`, `ingredients`, `equipment`, `prep`, `process`, `safety` |
| **R4 Bound plan** | Η συνταγή R3 συναρμολογημένη για *αυτή* την Mission: ακριβείς ποσότητες, επιλεγμένες παραλλαγές, ανατεθειμένοι acteurs και συσκευές, πρόγραμμα, μισθώσεις, παρακολούθηση, έκτακτα σχέδια | Ο planner/compiler, κατά το run time | Μέσα στην **Mission** (`plan`), ποτέ στον κατάλογο |

Όπως ο πηγαίος κώδικας και ένας μεταγλωττιστής: **η συνταγή είναι η φορητή ενδιάμεση αναπαράσταση
(R3 + R2). Η Αποστολή είναι η υπολογιστική μηχανή στόχος.** Αυτό είναι που κρατά τις συνταγές έγκυρες καθώς οι ρομπότ
και η AI αλλάζουν: ένας καλύτερος σχεδιαστής παράγει ένα καλύτερο R4 από την ίδια συνταγή.

## 2. Τι κάνει κάθε ενότητα σε μια Αποστολή

| Τμήμα συνταγής | Χρησιμοποιείται από το Mission για… |
|---|---|
| `identity.essential / flexible / neverAdd` | Αντικαταστάσεις, λειτουργίες προϋπολογισμού και επιδόσεων, προσαρμογές διατροφής: αλλάξτε τα flexible μέρη, ποτέ τα essentials, ώστε το πιάτο να παραμένει το ίδιο |
| `formula` (ratios, min/max, role, scaling) | Ακριβής scaling για οποιονδήποτε αριθμό ατόμων, διαμοιρασμός υλικών σε μια εβδομάδα, επέκταση προϋπολογισμού, χρήση αυτών που υπάρχουν ήδη (το rescale με περιοριστικό υλικό) |
| `sensory` | Σημεία ελέγχου όρασης, αρώματος και γεύσης; household taste profiles (αλάτι 2 έναντι 4); αποφάσεις επαναχρησιμοποίησης και διόρθωσης |
| `prep` (tools, surfaces, clearFirst, advanceTasks) | **Εργασίες προετοιμασίας περιβάλλοντος:** εάν ο νεροχύτης ή η εστία είναι κατειλημμένα, ο planner προσθέτει εργασίες "clear, wash, dry"; εργασίες για μουλιασμό ή αποψύξη προγραμματίζονται ώρες πριν |
| `process.nodes[]` με `pre`/`post` καταστάσεις τροφίμων | Σχεδιασμός (ξεκινήστε μόνο ό,τι είναι έτοιμο), επαλήθευση (παρήγαγε το βήμα την κατάσταση;), συνέχιση μετά από διακοπές |
| `until`, `onTimeout`, `retry` | Γνώση του πότε ένα βήμα ολοκληρώθηκε και τι πρέπει να γίνει όταν δεν έχει ολοκληρωθεί |
| `alternatives[]` + `energy` | Gas έναντι induction έναντι oven, battery saver, κουζίνες χωρίς oven, ώρες ησυχίας |
| `pause` (pausable, safeState, maxPause, onExceeded) | **Διακοπές:** ένα παιδί χρειάζεται βοήθεια, ο ιδιοκτήτης καλεί, ο σκύλος ανατρέπει κάτι. Το ρομπότ τοποθετεί το βήμα στην safe state του, διαχειρίζεται το γεγονός, και μετά συνεχίζει, ξαναζεσταίνει, σώζει ή απορρίπτει με βάση το pause budget |
| `failureModes` (incident, detect, prevent, playbook) | Έγκαιρη ανίχνευση γνωστών προβλημάτων και το ακριβές playbook για ανάκαμψη |
| `affordances`, `space` | Ταίριασμα βημάτων με ρομπότ που μπορούν να πιάσουν, να σηκώσουν και να φτάσουν; διατήρηση των hot zones μακριά από παιδιά |
| `safety` (hazards, CCPs, supervision, abort) | Το safety kernel: invariants που κάθε plan πρέπει να διατηρεί |
| `service` (temps, vessel, accompaniments, tableware, eating style, portioning, packable) | Σερβίρισμα: τι μπαίνει στο τραπέζι, στο δωμάτιο, στο lunchbox; υπενθυμίσεις και όρια αναμονής; cultural eating style |
| `storage` | Υπόλοιπα, Missions cook-ahead και lunchbox |
| `acceptance` | Τα *tests* της συνταγής: το Mission ολοκληρώνεται όταν αυτά ισχύουν |
| `nutrition`, `cost` | Προσωπικές μερίδες, προϋπολογισμός, επιδόσεις ανακούφισης |

## 3. Παράδειγμα: ένα βήμα με όλα τα συνημμένα

```json
{
  "id": "n7", "op": "cw.op.simmer",
  "inputs": ["aromatic_base", "tomato", "salt", "blackpepper"], "output": "sauce",
  "params": { "heat": "medium_low", "lid": "off", "target": { "sensor": "cw.sense.liquid_temp", "value": 94, "unit": "degC", "tolerance": 3 } },
  "until": { "any": [ { "sensor": "cw.sense.mass_loss_ratio", "gte": 0.25 }, { "vision": "cw.sense.sauce_coats_spoon" } ],
             "minTime": "PT10M", "maxTime": "PT18M" },
  "onTimeout": "extend",
  "pause": { "pausable": true, "safeState": ["heat_hold_low", "lid_ajar"], "maxPause": "PT45M", "onExceeded": "reheat_then_resume" },
  "failureModes": [
    { "incident": "cw.incident.too_salty", "likelihood": "low", "playbook": "cw.pb.too_salty_liquid" },
    { "incident": "cw.incident.too_thin", "likelihood": "medium", "playbook": "cw.pb.sauce_too_thin" } ],
  "alternatives": [ { "id": "gas", "op": "cw.op.simmer", "when": ["gas_only"], "timeFactor": 1.0, "quality": "same" } ],
  "hazards": ["hz_splatter", "hz_steam"], "attention": "monitor"
}
```

## 4. Σύνταξη μιας συνταγής για μια Mission (τι κάνει ο planner)

1. **Επιλέξτε τη παραλλαγή:** διατροφή, υφή (IDDSI), εξοπλισμός, επιλογή ενέργειας και λειτουργίας από τα
   `alternatives`. Τα θεμελιώδη στοιχεία ταυτότητας πρέπει να επιβιώνουν.
2. **Κλιμάκωση:** από τη `formula` και τις μερίδες, τις μερίδες ανά άτομο (HEALTH.md), το
   περιοριστικό συστατικό, ή έναν ορίζοντα επιδόσεων. Μπαχαρικά υπογραμμικά, χρόνος βάσει εκθέτη μάζας.
3. **Αντικατάσταση** εντός ρόλων, σεβασμό στην `identity.neverAdd`, τις αλλεργίες, τα διατροφικά πακέτα
   και το απόθεμα.
4. **Προετοιμασία περιβάλλοντος:** σύγκριση του `prep` με τα facets του χώρου της Αποστολής (γεμάτος νεροχύτης;
   κατειλημμένη κουζίνα; λερωμένη σανίδα;) και προσθήκη εργασιών τακτοποίησης, πλυσίματος, στεγνώματος και προετοιμασίας. Προγραμματισμός
   `advanceTasks` (μουλιασμός, αποψύξη, μαρινάρισμα, προθέρμανση).
5. **Σύνδεση:** ανάθεση κάθε κόμβου σε ρομπότ, συσκευές ή ανθρώπους βάσει affordances και
   ικανοτήτων. Νοικίαση εστιών, σκευών και ζωνών. Σύνδεση μονιτόρων (έξυπνο καχύ, ETA παράδοσης, ανιχνευτή καπνού).
6. **Προγραμματισμός** προς τα πίσω από την ώρα σερβιρίσματος, σεβασμός στα προϋπολογισμούς παύσης, στα όρια μπαταρίας και ενέργειας,
   στις ώρες ησυχίας του νοικοκυριού και στα παράθυρα κοινής χρήσης της κουζίνας.
7. **Επισύναψη έκτακτων περιπτώσεων:** τους `failureModes` και τους κανόνες `pause` κάθε κόμβου, καθώς και τις
   παγκόσμιες πολιτικές της Αποστολής (διακοπές, παιδί ή κατοικίδιο κοντά στην κουζίνα, watchdog κουζίνας,
   παρακολούθηση αλλοίωσης).
8. **Επαλήθευση:** έλεγχοι schema + σημασιολογικοί, πακέτα πολιτικών, κάλυψη CCP, simulator dry-run,
   αμετάβλητα priority-stack (PROTOCOL §7.2).
9. **Έκδοση R4** στο `plan` της Αποστολής, υπογραφή και παράδοση στο ρομπότ.

## 5. Συγγραφή και μετατροπή

- **Από το fifi.cooking:** η pipeline EXPORT-FIFI δημιουργεί R1 + R2 + R3. Οι νέες
  ενότητες (identity, sensory, formula, prep, service, pause, failureModes, affordances)
  παράγονται από τοπικά μοντέλα από το υπάρχον κείμενο και ελέγχονται από validators και
  δειγματοληπτική ανθρώπινη αναθεώρηση.
- **Από το web:** `cookwala convert --from schema-org` → R1/R2 (V0), στη συνέχεια η ίδια
  εμπλουτισμός.
- **Σε άλλα formats:** schema.org Recipe (R1/R2 για μηχανές αναζήτησης), Cooklang (ανθρώπινη
  επεξεργασία), PDDL ή temporal logic (research planners) μπορούν και αυτά να παραχθούν από το R3.
- **Με το χέρι:** `cookwala init recipe` δημιουργεί το σκελετό όλων των επιπέδων; `cookwala validate` και
  `cookwala simulate` τα ελέγχουν.
- **Versioning:** οι αναθεωρήσεις είναι αμετάβλητες και με hash. Τα forks καταγράφουν το `meta.derivedFrom`.
  Τα **patches** των recipes (από playbooks ή feedback) προτείνονται ως diffs και προωθούνται μόνο
  μετά από αναθεώρηση και evidence.

## 6. same language του step text

Οι προτάσεις βημάτων είναι γραμμένες για έναν άνθρωπο πρώτα και αναλύονται από μια μηχανή δεύτερη. Το κείμενο βήματος στα αραβικά στις παραδείγματα συνταγές χρησιμοποιεί την επιτακτική της γυναικείας πρόθεσης (قطّعي، سخّني), που είναι η κοινή αιγυπτιακή συνάθηση βιβλίων μαγειρικής· είναι μια σκόπιμη επιλογή, όχι παραλείψη, και ένας εκδότης μπορεί να χρησιμοποιήσει την ουδέτερη παθητική φωνή (تُقطَّع البصلة) αντί αυτού. Τα πεδία `op`, `params` και `until` μεταφέρουν το νόημα· η πρόταση προορίζεται για τον μάγειρα.

## 7. Γιατί αυτό παραμένει προσαρμοστικό στο μέλλον

- Οι συνταγές περιγράφουν **food outcomes and constraints, όχι κινήσεις**. Νέα ρομπότ και νέα AI
  παράγουν καλύτερα σχέδια R4 από το ίδιο R3.
- Όλα τα νέα τμήματα είναι **προαιρετικά και προσθετικά**. Μια συνταγή V0 (μόνο R1) λειτουργεί ακόμα για
  καθοδηγούμενο μαγειρέρεμα από ανθρώπους; κάθε προστιθέμενη στρώση ξεκλειδώνει περισσότερη αυτοματοποίηση.
- Άγνωστα πεδία `x-` περνούν απευθείας. Προμηθευτές, σεφ και φορείς υγείας μπορούν να επεκτείνουν συνταγές
  χωρίς να επηρεάζουν κανέναν.
- **Acceptance checks** επιτρέπουν σε οποιονδήποτε εκτελεστή, άνθρωπο ή ρομπότ, να αποδείξει ότι το πιάτο βγήκε σωστά,
  αυτός είναι ο τρόπος με τον οποίο οι συνταγές φτάνουν στο V3 με field evidence.
