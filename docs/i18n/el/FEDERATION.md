# Ομοσπονδία: πώς λειτουργεί η Cookwala χωρίς κέντρο

**Status:** draft, 2026-10-04 (RFC-0006). Η φωτογραφία του ιδρυτή ήταν μια μελισσαρή: χωρίς κεντρική
διοίκηση, κι όμως αρμονία και ανάκαμψη. Αυτή η σελίδα λέει τι σημαίνει αυτό στην πράξη.

## 1. Nodes

| Node | Τι εξυπηρετεί | Ποιος εκτελεί έναν |
|---|---|---|
| **Catalog** | `/.well-known/cookwala.json`, recipes, vocabularies, rule packs, keys, feeds | ένας εκδότης συνταγών, ένα food-bank network, ένα πανεπιστήμιο, ένας κατασκευαστής συσκευών, cookwala.ai |
| **Registry** | `/v1/registry.json`: pointers to catalogs, collections, devices, packs, benchmarks | οποιοσδήποτε; το cookwala.ai εκτελεί έναν |
| **Hub** | το Core API για μια κουζίνα, τοπικά όρια ασφαλείας, το household context | κάθε κουζίνα; λειτουργεί offline |
| **Mirror** | επαναδημοσιεύει τα υπογεγραμμένα αντικείμενα άλλων nodes αμετάβλητα | οποιοσδήποτε επιθυμεί resilience στην περιοχή του |

Ένας στατικός φάκελος είναι ένα έγκυρο κατάλογο. Ένα τηλέφωνο με τα CSV templates είναι ένας έγκυρος ανθρωπιστικός
συμμετέχων στο επίπεδο H0.

## 2. Feeds, όχι commands

Οι κόμβοι δημοσιεύουν υπογεγραμμένα feeds: recalls, ανώνυμα περιστατικά, αλλαγές στο registry, βασικά αρχεία.
Άλλοι κόμβοι κάνουν poll σε όσα εμπιστεύονται και ενδέχεται να τα επαναδημοσιεύσουν. Τίποτα δεν σπρώχνεται σε μια κουζίνα (kitchen); μια
κουζίνα κάνει pull όταν είναι online και συνεχίζει να λειτουργεί όταν δεν είναι.

## 3. Επαληθεύστε σε σχέση με τον εκδότη, ποτέ με τον relay

Ένα recall που φτάνει μέσω ενός mirror είναι καλό μόνο όσο η υπογραφή του **issuer**. Ένα hub
επιλύει το `KeyRecord` του issuer από το δικό του discovery document ή did:web και
επαληθεύει το body byte for byte. Το key του mirror δεν αποδεικνύει τίποτα για το περιεχόμενο· ένα mirror
που επεξεργάζεται ένα recall σπάει την υπογραφή. Τα profile vectors στο `conformance/profiles/federation.json`
επιδείκνουν τα τρία przypadρια.

## 4. Λίστες εμπιστοσύνης

Κάθε hub διατηρεί μια λίστα από καταλόγους και registries στα οποία εμπιστεύεται, με τα κλειδιά τους και μια προτεραιότητα. Ένα node μπορεί να προτείνει peers (`federation.peers`); το hub αποφασίζει. το cookwala.ai είναι μία είσοδος σε μια τέτοια λίστα, όχι ένα root.

## 5. Φρεσκάδα

Οι εγγραφές στο registry φέρουν ένα status και έναν χρόνο δημοσίευσης· τα recalls φέρουν έναν χρόνο έκδοσης· τα household facets φέρουν μια εγκυρότητα. Τα παλαιά items ανακτώνται ξανά ή απορρίπτονται. Τίποτα δεν εμπιστεύεται επειδή είναι παλιό, τίποτα δεν διαγράφεται σιωπηλά: οι withdrawn entries παραμένουν ως tombstones.

## 6. Ιστορικό

Τα αρχεία καταγραφής γεγονότων με μαρτυρούμενα σημεία ελέγχου (Core section 5) καθιστούν τις αναγραφές επιdetectable χωρίς ένα blockchain: ένα δεύτερο μέρος υπογράφει την κεφαλή του αρχείου καταγραφής, και μια later αναγραφή δεν ταιριάζει πλέον. Η δημόσια αγκύρωση των κεφαλών των σημείων ελέγχου είναι προαιρετική και αποτελεί απόφαση των ιδρυτών (`docs/research/BACKSTORY.md` section 4.7).

## 7. Τρεις κόμβοι που συνεργάζονται μεταξύ τους

- **Ένα δίκτυο food bank** διαχειρίζεται ένα registry των κουζινών και των δωρητών του, έναν κατάλογο των rule packs του προσαρμοσμένων στο εθνικό δίκαιο, και μια πύλη SMS. Εμφανίζεται στον Cookwala.ai directory ή όχι· τα δεδομένα του δεν πρέπει ποτέ να εγκαταλείπουν τη χώρα του.
- **Ένας κατασκευαστής συσκευών** διαχειρίζεται έναν κατάλογο των εγγράφων δυνατοτήτων και των safety-limit packs του, δημοσιεύει αναφορές conformance, και ελέγχει τα recall feeds των καταλόγων που χρησιμοποιούν οι πελάτες του.
- **Ένα πανεπιστημιακό εργαστήριο** διαχειρίζεται έναν κατάλογο από recipes πρότυπα και execution logs (με συγκατάθεση), καθρεφτίζει τα λεξιλόγια, και δημοσιεύει τα δικά του vectors.

Κανένα από αυτά δεν χρειάζεται το cookwala.ai να είναι online.

## 8. Τι δεν έχει κατασκευαστεί

Ένας κεντρικός συντονιστής, ένας κεντρικός πάροχος ταυτότητας, ένα token, ένα blockchain. Οι αποφάσεις quorum και οι συντονιστές του προφίλ Mission παραμένουν προαιρετικοί και πειραματικοί.
