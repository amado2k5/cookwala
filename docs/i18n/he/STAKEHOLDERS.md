# בעלי עניין: הודעה, אפשרויות, הצלחה ראשונה ותזרים עבור כולם

**Status:** 2026-10-04. עבור כל קבוצה: מדוע Cookwala חשובה להם, דרכים למעורבות מקלה עד עמוקה, הצלחה ראשונה תוך פחות מ-15 דקות, הנתיב שאחריה, וכיצד מעורבות מקדמת את עבודתם ואת העולם. שום דבר כאן אינו מציין שותף, משתמש או פיילוט שאינם קיימים. במקום שבו משהו מתוכנן, נכתב next או later.

שלושת המטרות מאחורי כל שורה: לסייע בסיום הרעב, להפוך אנשים לבריאים יותר, ולהציב רובוטים לעבודה עבור אנשים.

## 1. בונים: מפתחים, יצרני רובוטים ומכשירי חשמל, מהנדסי מערכות משובצות (embedded engineers), בוני סוכני AI, מפתחי בתים חכמים ופלטפורמות, תורמי קוד פתוח

**הודעה.** רובוטים ומכשירים לומדים לנוע. איש לא רשם, בצורה שניתן לבדוק באמצעות מכונה, מה המשמעות של "simmer", מתי עוף הוא בטוח, או מתי יש לסרב לצעד מסוים. Cookwala הוא השכבה הזו: מתכונים שמכונה יכולה לתכנן, תנאי סיום שהיא יכולה למדוד, ומגבלות בטיחות שהיא אוכפת על עצמה. הוא פתוח, ללא תמלוגים, ניטרלי למודל וניטרלי למכשיר, והוא מגיע עם חבילת conformance שניתן להריץ כבר היום.

**אפשרויות.**
- *Light:* בצע dry run בדפדפן; קרא Core 0.2 (ערב אחד).
- *Medium:* `pip install -e sdk/python`, בצע dry-run ליכולות של המכשיר שלך מול מתכוני הדוגמה, הרץ את וקטורי ה-conformance, הפעל את ה-hub הייחוס.
- *Deep:* ממש את Core API על מכשיר או על hub, פרסם דוח conformance, הוסף את המכשיר שלך ל-directory, הצע RFC, כתוב ROS 2 bridge node, הוסף מקרי תקיפה ל-agent-safety benchmark.

**הצלחה ראשונה (מתחת ל-15 דקות).**
```bash
git clone https://github.com/amado2k5/cookwala && cd cookwala && pip install -e sdk/python
cookwala dryrun examples/koshari.cookwala.json --device examples/capabilities/robot-arm.json
# refused: cw.op.boil, missing_capability (and later: no oil thermometer, no deep frying)
cookwala dryrun examples/koshari.cookwala.json --device examples/capabilities/robot-arm.json --human-present
cookwala conformance --report report.json          # 106 vectors; a signed-ready report
```

**Flow.** dry run → יישום ה-Core API מול ה-hub הייחוס → מעבר conformance →
פרסום הדו"ח → רישום המכשיר → execution logs שקיבלו הסכמה הופכים ל-LeRobot datasets ו-OpenTelemetry traces.

**כיצד זה מקדם את עבודתם.** הגדרת משימה משותפת ומבחן הצלחה לבישול, עם
benchmark ציבורי למדידה; מתכונים בכל מטבח ללא כתיבתם; סיפור בטיחות שרגולטורים יכולים לקרוא; דוחות conformance כדוקומנט מכירה; מעמד של ראשוניות בתקן שיונה על ידי המיישמים שלו.

**כיצד זה מקדם את החברה.** פחות שריפות מטבח ומחלות המועברות במזון ממכונות ש-refusal before heat במקום לנחש; מכונות שיורשות את המטבחים של העולם במקום רק כמה.

## 2. חברות: סטארט-אפים, ארגונים, חברות מזון, קמעונאים ושליחויות, מסעדות ושירותי מזון, מבטחים, גופי conformance, צוותי מכירות ושותפויות

**הודעה.** כל חברה שנוגעת במזון תפגוש מכונות בישול וסוכני AI בשנים הקרובות. Cookwala נותנת לך ממשק אחד עבור כולם, היחיד עם מגבלות בטיחות המופעלות על המכשיר ורישומים שניתן לבצע להם audit. עבור קמעונאים ושירותי משלוחים: קבלת חלונות משלוח ודרישות אלרגנים, לעולם לא לוח זמנים של משפחה. עבור מבטחים וגופי certification: פורמט של דוח conformance ופיד של דיווח אירועים המיועד עבורך.

**אפשרויות.**
- *Light:* קרא את דף ה-Investors and partners ואת דפי ה-trust; מיפה את המוצרים שלך אל
  מחלקות הרכיבים וה-operations.
- *Medium:* פרסם offer feed (market profile, experimental) או surplus offer לתוכנית
  מקומית (Humanitarian Profile); הרץ את ה-agent-safety benchmark על ה-agent שאתה
  מתכנן לפרוס.
- *Deep:* הטמע את ה-Core API במוצר; רדום על conformance verification; הצטרף ל-steering
  committee כשישתכלל; אמץ את ה-certification path.

**הצלחה ראשונה.** המר קו מוצרים אחד ל-`Offer` שוק עם GTINs ופרטי אלרגנים, ו validates אותו, וראה אילו מתכוני דוגמה הוא יכול לספק.

**Flow.** הצעה להזנה → derived constraints ממשקי בית → הזמנות דרך ה-checkout שלך → אירועי fulfillment → מוניטין מדווחות execution (בהסכמה).

**כיצד זה מקדם את עבודתם.** גישה לשכבה ניטרלית במקום תריסר אינטגרציות של ספקים; אותות ביקוש (later, לאחר בדיקת דיני תחרות) המפחיתים בזבוז; certification שחברות ביטוח יכולות לתמחר; רישום ציבורי של בטיחות.

**כיצד זה מקדם את החברה.** פחות מזון שאובד בין החנות לצלחת; surplus המגיע למטבחים לפני שהוא נרקב; מכונות בבתים שלא ניתן לשכנע לביצוע פעולות לא בטוחות.

## 3. ספקים: מכולות, חוות וקואופרטיבים, משלוחים, אנרגיה, ספקי AI ומודלים, מוציאים לאור מתכונים

**Message.** ספקים מתחברים ל-Cookwala כעמיתים, לא כדיירים. מכולת או שירות משלוחים
מקבלים constraint, לעולם לא את העובדות של משק בית. ספק AI מקבל benchmark המראה שהמודל
שלו בטוח במטבח ושרת MCP לשימוש היום. מוציא לאור מתכונים שומר על שמו
על כל מתכון ויכול לפרסם קטלוג חתום מתוך תיקייה סטטית.

**אפשרויות.** פרסם קטלוג (מתכונים) · פרסם פיד הצעות · הרץ את ה-agent-safety benchmark · הרץ registry node · הצע surplus באמצעות SMS.

**הצלחה ראשונה.** מפרסם מתכונים: `cookwala init my-dish`, עריכה, `cookwala validate`,
`cookwala hash`; הקטלוג שלך הוא תיקייה עם `/.well-known/cookwala.json`. ספק AI:
הוסף את שרת ה-MCP והרצ את עשרת מקרי ה-agent-safety.

**Flow.** קטלוג או הזנה → רשומת registry תחת ה-namespace המוכח שלך → recall feed אם
משהו משתבש → מוניטין מתוצאות.

**כיצד זה מקדם את עבודתם.** להגיע לכל מכשיר וסוכן דרך פורמט אחד;
קרדיט ומקור על ידי חתימה; מדד בטיחות המהווה נכס שיווקי כאשר
הוא עובר ביושר.

**כיצד זה מקדם את החברה.** מתכונים נשארים מיוחסים; סוכנים שפועלים עבור אנשים הם
measured לפני שניתן לסמוך עליהם.

## 4. מזון: חקלאים, טבחים ושפים, טבחים ביתיים, יוצרי מתכונים, בתי ספר לקולינריה

**הודעה.** מתכון שנכתב עבור Cookwala שומר על שמך ועל המטבח שלך חיים בכל
מכשיר שמבשל אותו, עם הצעדים שמכונה לעולם לא צריכה לדלג עליהם כתובים. חווה עם
עודף יכול לרשום אותו באמצעות SMS ולהגיע למטבח באותו היום. בית ספר לקולינריה יכול ללמד בטיחות
מזון בפורמט שבודק את עצמו.

**אפשרויות.**
- *חקלאים:* `FARM 120KG TOMATO A BB0411` לשער של תוכנית (במידה וקיים);
  later, קרא אותות היצע וביקוש.
- *טבחים ושפים:* הפוך מתכון אחד שאתה מכיר בעל פה למתכון Cookwala; סקור את
  משפטי השלבים בשפה שלך; later, הקלט מפגשים מוסכמים עם קרדיט.
- *בתי ספר:* השתמש בתשעת מתכוני הדוגמה כמקרי לימוד; הוסף משלך.

**הצלחה ראשונה.** טבחים: `cookwala init`, כתיבת מתכון אחד עם תנאי סיום עבור כל שלב חום, אימות שלו. חקלאים: שליחת הצעת SMS אחת לתוכנית שמריצה את הפרופיל (אף אחת עדיין לא מריצה; ה-parser וה-vectors קיימים).

**Flow.** מתכון → validation → catalog → dry run במכשירים → execution logs מראים כיצד הוא
מתפקד במכונות אמיתיות → עדכונים עם evidence.

**כיצד זה מקדם את עבודתם.** ייחוס שנודד; מתכון שניתן לבשל על ידי מכונות במדינות אחרות; עבור חקלאים, דרך להפוך עודף לארוחות במקום לפסולת.

**כיצד זה מקדם את החברה.** מורשת קולינרית נשמרת כידע מעשי, לא כסרטון;
פחות פסולת בשער החווה.

## 5. הומניטרי: NGOs, food banks, מטבחים קהילתיים, תוכניות ארוחות בית ספריות, סוכנויות סיוע, תורמים

**הודעה.** ה-Humanitarian Profile מעביר surplus food לצלחות באמצעות טלפונים וגיליונות אלקטרוניים, מתעד בדיקות שרשרת קירור, סופר ארוחות, ואינו נושא **no personal data**. הוא פועל ללא רובוטים, אפליקציות או אינטרנט. הוא מספק לך מספרים שניתן להגן עליהם: קילוגרמים שהצליחו, ארוחות שהוגשו, שיעור מעבר תזונתי, עלות לארוחה, זמן לתביעה, תקריות בטיחות, כל אחד בשיטה שלו.

**אפשרויות.**
- *Light:* קרא את הפרופיל ואת פרוטוקול הפיילוט; נסה את ה-SMS walkthrough.
- *Medium:* הרץ את תבניות ה-CSV באתר אחד למשך ארבעה שבועות (רמה H0) וחשב
  סיכום השפעה.
- *Deep:* פיילוט רשום מראש למשך 12 שבועות עם baseline ומעריך עצמאי;
  התאם את ה-rule packs לחוק הלאומי עם מוביל בטיחות המזון שלך; הרץ את ה-registry
  node שלך.

**הצלחה ראשונה.** מלא את שלושת תבניות ה-CSV עבור יום אחד, הרץ
`cookwala humanitarian --summary your-folder`, קרא את ה-`ImpactSummary` עם שיטה תחת
כל מספר.

**Flow.** הצעה → תביעה → מסירה עם בדיקת טמפרטורה → הפצה → סיכום השפעה → תוצאות שפורסמו, מה שלא יראו.

**כיצד זה מקדם את עבודתם.** מספרים דומים בין אתרים; ראיות עבור מממנים;
ממצאי בטיחות לפני, ולא אחרי, בעיה; פורמט שמערכות של תורמים יכולות לקרוא (HXL,
GS1, DHIS2 mappings).

**כיצד זה מקדם את החברה.** יותר מזון שמגיע לאנשים בבטחה, כשהכבוד שלהם נשמר:
ללא שמות, ללא פנים, ללא profiling.

## 6. בריאות: תזונאים, מפקחי בטיחות מזון, סוכנויות בריאות הציבור, בתי אבות

**Message.** חוקי תזונה ובטיחות מזון כחבילות הניתנות לבדיקה מכנית, הנגזרות מהנחיות ציבוריות, המיושמות על תפריטים ומסירות, כאשר הסקירה שלך מתועדת לפי מקצוע ותוצאה. דבר אינו ייעוץ רפואי; דבר אינו נטען מעבר למה שנאמר בחבילות.

**אפשרויות.** סקור pack עם התבנית (שעתיים) · התאם pack לכללים לאומיים ·
הצע כללי טיפול עבור האנשים שאתה משרת · later, קרא תוצאות מצטברות מתוכניות.

**הצלחה ראשונה.** פתח את `profiles/humanitarian/care-vulnerable-groups.rulepack.json` וכן
את תבנית הסקירה; סמן שלוש חוקים כמאושרים, שונו או נדחו; הגש את הסקירה.

**Flow.** Draft pack → review → status reviewed → programs adopt → findings in every
distribution → outcomes published with methods.

**כיצד זה מקדם את עבודתם.** ההדרכה שלך פועלת בכל מטבח שמאמץ אותה,
כולל מטבחי רובוטים, עם המקצוע שלך מתועד; סקירה שניתן לפרסם;
מערך נתונים של ממצאים (אגרגטיבי, ללא נתונים אישיים) למחקר.

**כיצד זה מקדם את החברה.** פחות נתרן, סוכר ושומן רווי בארוחות המוגשות בהמוניהן; שמירה בטוחה יותר על חום וקירור; טיפול בילדים ובקשישים המוטמע במכונה.

## 7. חינוך: מורים בבתי ספר, אנשי חינוך, פרופסורים, חוקרים, סטודנטים

**Message.** בישול הוא התהליך המוכר ביותר בעולם, ו-Cookwala הופכת אותו ל
אובייקט לימודי: טמפרטורות, יחידות, חלוקה הוגנת, בטיחות, מכונות שפועלות לפי חוקים. עבור
חוקרים זהו benchmark, פורמט של dataset ורשימת בעיות פתוחות.

**אפשרויות.**
- *מורים:* ערכת השיעור (`docs/education/LESSON-KIT.md`): חמישה שיעורים מ-"מהו simmer" ועד "מה מכונה לעולם לא צריכה לעשות".
- *פרופסורים וסטודנטים:* רשימת נושאי המחקר, הסימולטורים, וקטורי ה-conformance כתנאי בדיקה, ה-LeRobot export, בעיות פתוחות בגודל תזה.
- *חוקרים:* פרסום מערכי נתונים של executions בהסכמה; ביקורת על ה-assumptions של הסימולטורים; הצעה של וקטורים.

**הצלחה ראשונה.** מורים: הריצו את ה-dry run של הדפדפן בכיתה ושאלו מדוע המכשיר
סירב. תלמידים: שנו הנחה אחת בסימולטור העיר והסבירו את התוצאה.

**Flow.** שיעור → פרויקט → סט נתונים → מאמר → RFC.

**כיצד זה מקדם את עבודתם.** חומר חופשי, פתוח וניתן לציטוט; benchmark שאיש אינו מחזיק בו;
שותפות בכתיבת הסטנדרט באמצעות RFCs.

**כיצד זה מקדם את החברה.** דור שיודע מהי מטבח בטוח ויכול לקרוא גיליון בטיחות.

## 8. ממשלה: ממשלות, משרדים, פקידי עירייה, רגולטורים, פוליטיקאים ומחוקקים, גופים ממשלתיים וגופי תקנים

**הודעה.** מכונות בישול ביתיות ומסחריות מגיעות תחת תקנות שנכתבו עבור מכשירים ותוכנה בנפרד. Cookwala נותנת לרגולטורים משהו מוחשי להצביע עליו: מגבלות בטיחות המונפות על המכשיר, refusal before heat, רשומות חתומות, דיווח אירועים אנונימי, ומערכת conformance שכל אחד יכול להריץ. עבור בטיחות תרומת מזון היא מספקת תקן נתונים ללא נתונים אישיים. היא ללא תמלוגים ובדרך לממשל ניטרלי.

**אפשרויות.** קרא את תמצית המדיניות (`docs/policy/BRIEF.md`) · השתמש בשפת המודל עבור נתוני תרומות מזון ובטיחות מכונות בישול · בקש מגוף התקנים שלך לבחון את Core 0.2 · הפעל צומת registry לאומית · מימן פיילוט עם תוכנית ארוחות בית הספר שלך.

**הצלחה ראשונה.** קרא את התקציר בן שני העמודים ובדוק שלושה דברים במאגר (repository): ה-safety limits pack, ה-conformance runner, וחוקי הגנת המידע ההומניטריים.

**Flow.** קצר → סקירה על ידי גוף תקנים לאומי → התייחסות בהנחיות → פיילוט →
תכנית certification.

**כיצד זה מקדם את עבודתם.** בסיס טכני מוכן וניתן לבדיקה; ראיות ממאמצי dry run; ערוץ לתעשייה באמצעות תקן ניטרלי; יכולת פעולה משותפת (interoperability) עם תקני הנתונים ההומניטריים שבהם אתם כבר משתמשים.

**כיצד זה מקדם את החברה.** מכונות בטוחות יותר בבתים; הצלת מזון המגנה על האנשים
שהיא משרתת; פחות פסולת בערים.

---

## 9. הון: משקיעים, יזמים, פילנתרופיות, בנקי פיתוח

**Message.** הבישול עומד להפוך לתשתית. הסטנדרט הוא בחינם; השירותים
סביבו הם עסק: certification, תוכנת hub, מערכי נתונים בהסכמה, פעולות
registry, פיילוטים. השכבה ההומניטרית היא טווח ציבורי שמממני פיתוח יכולים
לתמוך בו באמצעות הערכה רשומה מראש. לא ניתנות הבטחות פיננסיות בשום מקום באתר זה.

**אפשרויות.** קרא את ההזדמנות, המודל העסקי, מפת הדרכים, הסיכונים והממשל
(`/investors`) · מימן dry run או סקירה · תמוך בחברה שמוכרת שירותים לצד הסטנדרט
החינמי · הצטרף לממשל כמשקיע צופה.

**הצלחה ראשונה.** קרא את סעיפי הבעיה, הארכיטקטורה והסיכונים של ה-whitepaper ואת רישום החששות של תוכנית הפעולה; כל סיכון פתוח רשום.

**Flow.** ראיות (pilots, conformance, adopters) → שערים בתוכנית הפעולה → מימון הקשור לשערים → בסיס ניטרלי לתקן, חברה לשירותים.

**כיצד זה מקדם את עבודתם.** מיקום מוקדם בתקן מגדיר-קטגוריה עם מספרים כנים; חברת שירותים ראויה להשקעה המופרדת מהטוב הציבורי.

**כיצד זה מקדם את החברה.** הון מופנה למה ש-measured, לא למה שנטען.

---

## 10. מחשבה: פילוסופים, אתיקנים, היסטוריונים ופיוטריסטים

**הודעה.** כאשר מכונה מבשלת מתכון של סבתא, למי שייך הידע? מה המשמעות של כבוד בטיפול אוטומטי? מה רובוט של משק בית עשוי לדעת, ומי עוד עשוי לדעת זאת? Cookwala קיבלה החלטות לגבי שאלות אלו בקוד; המאמרים (`docs/essays/`) אומרים מה הן היו ומזמינים חילוקי דעות.

**אפשרויות.** קרא את המאמרים · כתוב תגובה · הצע כלל (RFC הוא טיעון פילוסופי עם סכימה) · שים את עצמך בביקורת האתיקה של ה-household context profile.

**הצלחה ראשונה.** קרא את המאמר על household data ואת חוקי הנסיעה של facet registry;
מצא facet אחד שהברירת מחדל שלו היית משנה, וציין מדוע.

**Flow.** מסה → הערה ציבורית → RFC → ברירת מחדל שונתה.

**כיצד זה מקדם את עבודתם.** מקרה חי שבו עמדות אתיות הופכות לכללים פעילים,
עם תיעוד ציבורי של הטיעון.

**כיצד זה מקדם את החברה.** החלטות לגבי נתונים אינטימיים וירושה תרבותית המתקבלות
בגלוי לפני שהמכונות יגיעו במיליוני בתים.

---

## 11. כולם: אנשים שאכפת להם מאוכל, פסולת, עבודה, אקלים והעתיד

**הודעה.** Cookwala היא דרך לכתוב מתכון כך שכל אחד, או כל דבר, יוכל לבשל אותו בבטחה, ודרך עבור מזון שעלול להיזרק להגיע למי שזקוק לו. היא בחינם, היא אינה שייכת לאף חברה, והיא אומרת מה היא אינה יודעת.

**אפשרויות.** נסה את ה-dry run · הפעל סימולטור · קרא את המתכונים · כתוב מתכון אחד שאתה
אוהב · פעל לפי מפת הדרכים · ספר על כך ל-food bank או לבית ספר.

**הצלחה ראשונה.** שנה את המכשיר ב-dry run וצפה בשלב שנדחה; קרא מדוע.

**Flow.** סקרנות → מתכון אחד → שיחה אחת עם מטבח שיכול להשתמש בו.

**כיצד זה מקדם את חייהם.** מכונות בטוחות יותר בבית, המתכונים שלהם נשמרים,
דרך לעזור מבלי לתת כסף.

**כיצד זה מקדם את החברה.** פחות פסולת, מזון בטוח יותר, מכונות המשרתות אנשים שאינם יכולים לבשל עבור עצמם, וזמן אנושי שמוחזר.
