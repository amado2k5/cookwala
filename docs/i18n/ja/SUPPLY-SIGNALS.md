# 農場のsurplusおよび供給シグナル

> **Status: experimental** (RFC-0007). Schema: `schemas/supply.schema.json`. Examples:
> `examples/supply/`. **Gate:** 本番利用前の競争法レビュー
> (`docs/ACTION-PLAN.md`, concern C7). cookwala.ai は現在、いかなるシグナルも公開していません。

## 1. 農家が今必要としている2つのこと

1. **腐敗する前に余剰をリスト化する方法。** 人道支援プロファイルにおいて、農場はドナーとなります：
   `Item.origin: farm` と `harvestedAt` を持つ `Offer`、またはSMSによって：

   FARM 120KG TOMATO A BB0411
   ```

food bank がそれを主張し、キッチンがそれを調理し、流通がそれをカウントする。新しいドキュメントなし、個人データなし、組織のみ。
2. **何が必要になるかを示す公平なシグナル。** それが以下の実験的な部分である。

## 2. 需要と供給のシグナル

| ドキュメント | 内容 | ルール |
|---|---|---|
| `DemandSignal` | 地域 R において、ISO 週 W に、キッチンおよびプログラムは **class** C の食材を L から H kg 使用する予定である | 少なくとも 20 の寄与ソースがあること; 週の終了から少なくとも 7 日後に公開されること; class レベル（legume, leafy vegetable, poultry）であり、製品やブランドではないこと; **価格は含まない**; 100 以上のソースがない限り、地域は admin1 より細かくないこと |
| `SupplySignal` | 地域 R において、週 W に、class C は収穫期間を伴う過剰、通常、または不足の状態である | 協同組合、プログラム、または市場運営者によって公開されること; **すべての人に公開**されていること: 公的、無料、かつすべての読者に対して同一であること |

リファレンスチェックは `tools/cookwala_ref.py` 内の `check_signal()` です。プロファイルベクトル (`conformance/profiles/signal.json`) は、何が受理され、何が拒否されるかを示しています。

## 3. なぜこれらのルールなのか

競合他社間での予測の共有は、競争当局が警告している情報交換です。集計、遅延、クラスレベル、価格を含まないこと、および公開による発行は、計画には有用であり、価格調整には無用なシグナルを維持します。しきい値は開始点であり、助言者と統計学者がそれらを設定すべきです。

## 4. 創業者のアイデアが何になるか

マクロループ (RFC-0007): 計画された調理 → 集計された需要 → 農場と店舗が必要とする計画 → 栽培、移動、廃棄の減少。都市、国、および世界のシミュレーターは、それぞれの仮定の下での影響の大きさを示しています（例示であり、予測ではありません）。これら2つの文書は、それに向かうための最小かつ誠実な一歩です。

## 5. Later

先行需要からの植え付けアドバイス；備蓄規模（完全にリーンなサプライチェーンは脆弱である）；地域間救済フロー；協同組合からのSMSによる供給シグナル。
