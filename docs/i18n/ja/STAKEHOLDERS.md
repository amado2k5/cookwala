# ステークホルダー：メッセージ、オプション、最初の成功、そして全員のためのフロー

**Status:** 2026-10-04. 各グループについて：なぜ Cookwala が彼らにとって重要なのか、軽い関わりから深い関わりまでのエンゲージメントの方法、15分以内での最初の成功、その後の道のり、そしてエンゲージメントが彼らの活動と世界をどのように前進させるか。ここには、存在しないパートナー、ユーザー、またはパイロットの名前は記載されていません。何かが計画されている場合は、next または later と記載されています。

すべての行の背後にある3つの目標：飢餓を終わらせるのを助け、人々をより健康にし、ロボットを人々のために働かせること。

---

## 1. ビルダー: 開発者、ロボットおよび家電メーカー、組み込みエンジニア、AIエージェントビルダー、スマートホームおよびプラットフォーム開発者、オープンソースコントリビューター

**メッセージ。** ロボットや家電は動き方を学習しています。「simmer」が何を意味するのか、鶏肉が安全な状態とはいつなのか、あるいはいつステップを refusal before heat しなければならないのかについて、機械がチェックできる形式で書き留めたものは誰も存在しません。Cookwala はそのレイヤーです。機械が計画できるレシピ、機械が測定できる終了条件、そして機械自身に強制できる安全制限を提供します。これはオープンで、ロイヤリティフリーであり、model-neutral かつ device-neutral であり、今日から実行できる conformance suite が付属しています。

**オプション**
- *Light:* ブラウザの dry run を実行する; Core 0.2 を読む (一晩)。
- *Medium:* `pip install -e sdk/python` を実行し、例示されたレシピに対してデバイスの機能を dry-run し、conformance ベクトルを実行し、リファレンス hub を起動する。
- *Deep:* デバイスまたは hub に Core API を実装し、conformance レポートを公開し、デバイスを directory に追加し、RFC を提案し、ROS 2 ブリッジノードを書き、agent-safety ベンチマークに攻撃ケースを追加する。

**最初の成功（15分未満）。**
```bash
git clone https://github.com/amado2k5/cookwala && cd cookwala && pip install -e sdk/python
cookwala dryrun examples/koshari.cookwala.json --device examples/capabilities/robot-arm.json
# refused: cw.op.boil, missing_capability (and later: no oil thermometer, no deep frying)
cookwala dryrun examples/koshari.cookwala.json --device examples/capabilities/robot-arm.json --human-present
cookwala conformance --report report.json          # 106 vectors; a signed-ready report
```

**Flow.** dry run → reference hub に対して Core API を実装 → conformance を通過 →
レポートを公開 → デバイスをリスト化 → 同意を得た execution logs が LeRobot データセットおよび
OpenTelemetry traces になる。

**それがどのように彼らの業務を前進させるか。** 料理のための共有されたタスク定義と成功テスト、および比較測定のための公開ベンチマーク。レシピを記述することなくあらゆる料理に対応。規制当局が読み取ることのできる安全性のストーリー。販売資料としての conformance レポート。その実装者によって管理される標準における、先行者としての地位。

**それがどのように社会を前進させるか。** 推測するのではなく refusal before heat を行う機械によって、台所の火災や食中毒が減少します。また、少数の料理ではなく、世界の料理を継承する機械となります。

## 2. 企業：スタートアップ、エンタープライズ、食品会社、食料品店および配送、レストランおよびフードサービス、保険会社、認証機関、販売およびパートナーシップチーム

**メッセージ。** 食品に携わるすべての企業は、今後数年以内に調理機器やAIエージェントに遭遇することになります。Cookwalaは、それらすべてに対して一つのインターフェースを提供します。これは、デバイス上で強制される安全制限と、監査可能な記録を備えた唯一のインターフェースです。食料品店および配送業者向けには、家族のスケジュールではなく、配送時間枠とアレルゲン要件を受け取ることができます。保険会社および認証機関向けには、専用に設計されたconformanceレポート形式とインシデントレポートフィードを提供します。

**オプション.**
- *Light:* Investors and partners ページと trust ページを読み、製品を ingredient classes と operations にマッピングします。
- *Medium:* オファーフィード（market profile, experimental）を公開するか、地域のプログラム（Humanitarian Profile）に surplus オファーを公開します。デプロイ予定のエージェントに対して agent-safety benchmark を実行します。
- *Deep:* 製品に Core API を実装します。conformance 検証をスポンサーします。steering committee が結成された際に加入します。certification パスを採用します。

**最初の成功。** 1つの製品ラインをGTINとアレルゲン資格情報を持つ市場 `Offer` に変換し、それを検証して、どの例示レシピを供給できるかを確認します。

**Flow.** フィードの提供 → 世帯からの derived constraints → 自身のチェックアウトを通じた注文 → 履行イベント → 実行レポートからのレピュテーション（同意がある場合）.

**それがどのように彼らの業務を前進させるか。** 多数のベンダー統合の代わりに中立的なレイヤーへのアクセス；廃棄物を削減する需要シグナル（later、競争法レビューの後）；保険会社が価格設定できる certification；安全性の公開記録。

**どのように社会を前進させるか。** 店舗から皿に至るまでの食品ロスが減少します。surplusが腐敗する前にkitchensに届きます。不安全な行動を促すことができない家庭内の機器。

## 3. プロバイダー: 食料品店、農場および協同組合、配送、エネルギー、AIおよびモデルベンダー、レシピ出版社

**メッセージ。** プロバイダーはテナントとしてではなく、ピアとして Cookwala に接続します。食料品店や配送サービスは制約を受け取りますが、世帯の事実を受け取ることは決してありません。AIベンダーは、そのモデルがキッチンにおいて安全であることを示すベンチマークと、今日から使用できる MCP サーバーを受け取ります。レシピ出版社は、すべてのレシピに自らの名前を保持し、静的フォルダから署名付きカタログを公開できます。

**Options.** カタログ (recipes) を公開する · オファーフィードを公開する · agent-safety benchmark を実行する · registry ノードを実行する · SMS で surplus を提供する。

**最初の成功。** レシピパブリッシャー: `cookwala init my-dish`、編集、`cookwala validate`、
`cookwala hash`。カタログは `/.well-known/cookwala.json` を含むフォルダです。AIベンダー:
MCPサーバーを追加し、10件のエージェントセーフティケースを実行してください。

**Flow.** カタログまたはフィード → あなたの証明された名前空間の下での registry エントリ → 何か問題が発生した場合は recall フィード → 結果からのレピュテーション。

**どのように彼らの業務を前進させるか。** 単一のフォーマットを通じてあらゆるデバイスとエージェントに到達します。署名によるクレジットとプロバナンス。誠実にパスした際にマーケティング資産となる安全ベンチマーク。

**どのように社会を前進させるか。** レシピの帰属は維持され、人の代わりに活動するエージェントは、信頼される前にmeasuredされます。

## 4. 食料：農家、料理人およびシェフ、家庭料理人、レシピ作成者、料理学校

**メッセージ。** Cookwalaのために書かれたレシピは、それを調理するすべてのデバイスにおいて、あなたの名前とあなたの料理を存続させ、機械が決してスキップしてはならない手順を書き記します。供給過剰の状態にある農場は、SMSでそれをリストに載せ、同日中にキッチンへ届けることができます。料理学校は、それ自体が自己検証を行うフォーマットを用いて、食品安全を教えることができます。

**Options.**
- *Farmers:* `FARM 120KG TOMATO A BB0411` をプログラムのゲートウェイ（存在する場合）へ；
  later、供給と需要のシグナルを読み取る。
- *Cooks and chefs:* 暗記しているレシピを1つ Cookwala レシピに変換する；自身の言語でステップの文章を確認する；later、クレジット付きで同意を得たセッションを記録する。
- *Schools:* 9つの例示レシピを教材として使用する；独自のものを追加する。

**最初の成功。** Cooks: `cookwala init` を実行し、すべての加熱ステップに対して終了条件を持つレシピを1つ書き、それを検証する。Farmers: プロファイルを実行するプログラムにSMSオファーを1件送信する（まだ実行されるものはありません。parser と vectors は存在します）。

**フロー。** レシピ → validation → catalog → デバイス上での dry run → execution logs が実機でのパフォーマンスを示す → エビデンスを伴う修正。

**それが彼らの仕事をどのように前進させるか。** 伝播する帰属; 他の国の機械でも調理可能なレシピ; 農家にとっては、余剰を廃棄物ではなく食事に変える方法。

**社会をどのように前進させるか。** 料理の遺産がビデオではなく、生きた知識として保存されます。農場段階での廃棄物が減少します。

## 5. 人道支援: NGO、food bank、コミュニティキッチン、学校給食プログラム、救援機関、ドナー

**メッセージ。** Humanitarian Profileは、スマートフォンとスプレッドシートを用いてsurplus foodを皿へと運び、コールドチェーンのチェックを記録し、食事の数を数え、**個人データは一切保持しません**。ロボット、アプリ、またはインターネットなしで動作します。救出されたキログラム、提供された食事数、栄養合格率、1食あたりのコスト、申請までの時間、安全上のインシデントなど、それぞれに手法を伴う、あなたが主張できる数値を提供します。

**オプション**
- *Light:* プロファイルとパイロットプロトコルを読み、SMSウォークスルーを試行する。
- *Medium:* 1つのサイトで4週間CSVテンプレートを実行し（レベルH0）、影響サマリーを算出する。
- *Deep:* ベースラインと独立した評価者を伴う、12週間の事前登録済みパイロット。食品安全責任者と共にrule packを国内法に適応させる。独自のregistryノードを実行する。

**最初の成功。** 1日分の3つのCSVテンプレートを入力し、
`cookwala humanitarian --summary your-folder` を実行して、
すべての数字の下にメソッドが記載された `ImpactSummary` を読み取ります。

**フロー。** 提供 → 請求 → 温度確認を伴う引き渡し → 分配 → 影響の要約 → 公開された結果、それが何を示しているかにかかわらず。

**それがどのように彼らの活動を前進させるか。** サイト間での比較可能な数値；資金提供者へのエビデンス；問題が発生した後ではなく、発生前の安全に関する知見；ドナーのシステムが読み取り可能なフォーマット (HXL, GS1, DHIS2 mappings)。

**社会をどのように前進させるか。** 人々の尊厳を損なうことなく、より多くの食料を安全に届ける：
名前なし、顔なし、プロファイリングなし。

## 6. 健康: 管理栄養士、食品安全担当官、公衆衛生機関、介護施設

**メッセージ。** 公的なガイダンスから派生し、メニューや引き継ぎに適用される、マシンでチェック可能なパックとしての栄養および食品安全ルール。あなたのレビューは職種と結果によって記録されます。いかなるものも医学的助言ではなく、パックに記載されていること以外の主張は一切行われません。

**Options.** テンプレートを使用してパックをレビューする（2時間） · パックを国内ルールに適応させる ·
提供する人々に対してケアルールを提案する · later、プログラムからの集計結果を読み取る。

**最初の成功。** `profiles/humanitarian/care-vulnerable-groups.rulepack.json` とレビューテンプレートを開き、3つのルールを approved、changed、または rejected とマークして、レビューを提出してください。

**Flow.** Draft pack → review → status reviewed → programs adopt → findings in every
distribution → outcomes published with methods.

**それが彼らの仕事をどのように前進させるか。** あなたのガイダンスは、ロボットキッチンを含む、それを採用するすべてのキッチンで実行され、あなたの専門性が記録され、出版可能なレビュー、および研究のための（集計された、個人データを含まない）知見のデータセットとなります。

**どのように社会を前進させるか。** 大量給食におけるナトリウム、糖分、飽和脂肪酸の低減。より安全な温熱保持および冷却。子供や高齢者への配慮が機械に組み込まれている。

## 7. 教育: 学校の教師、教育者、教授、研究者、学生

**Message.** 料理は世界で最も身近なプロセスであり、Cookwalaはそれを教育対象へと変えます：温度、単位、公平な分配、安全性、そしてルールに従う機械。研究者にとって、それはベンチマーク、データセット形式、そしてオープンな問題のリストです。

**オプション.**
- *教師:* レッスンキット (`docs/education/LESSON-KIT.md`): 「simmerとは何か」から「機械が決して行ってはならないことは何か」までの5つのレッスン。
- *教授および学生:* 研究トピックのリスト、シミュレーター、テスト条件としての conformance ベクトル、LeRobot エクスポート、論文規模の未解決問題。
- *研究者:* 同意を得た execution のデータセットを公開する; シミュレーターの assumptions を批判する; ベクトルを提案する。

**最初の成功。** 先生：授業中にブラウザの dry run を実行し、なぜデバイスが refusal before heat したのかを尋ねてください。学生：都市シミュレーター内の一つの assumed を変更し、その結果を説明してください。

**フロー。** Lesson → project → dataset → paper → RFC.

**それがどのように彼らの活動を前進させるか。** 無料で、オープンで、引用可能な資料；誰も所有しないベンチマーク；RFCを通じた標準への共同執筆。

**どのように社会を前進させるか。** 安全なキッチンとは何かを知り、安全シートを読める世代。

## 8. 政府: 政府、省庁、市当局、規制当局、政治家および立法者、統治・標準化機関

**メッセージ。** 家庭用および業務用調理機器は、家電製品とソフトウェアを個別に想定して作成された規制の下で導入されつつあります。Cookwalaは、規制当局に対して具体的な指針を提供します。それは、デバイス上で強制される安全制限、refusal before heat、署名済みの記録、匿名のインシデント報告、そして誰でも実行可能なconformanceスイートです。食品寄付の安全性については、個人データを含まないデータ標準を提供します。これはロイヤリティフリーであり、中立的なガバナンスを目指しています。

**オプション。** 政策概要 (`docs/policy/BRIEF.md`) を読む · 食料寄付データと調理機器の安全性にモデル言語を使用する · 標準化団体に Core 0.2 のレビューを依頼する · 国家 registry ノードを実行する · 学校給食プログラムでパイロットに資金提供する。

**最初の成功。** 2ページの概要を読み、リポジトリ内の3つの項目を確認してください：
safety limits pack、conformance runner、humanitarian data-protection rules。

**フロー。** 簡潔なもの → 国家標準機関によるレビュー → ガイダンスでの参照 → パイロット →
certification scheme。

**それがどのように彼らの業務を前進させるか。** すぐに利用可能で、レビュー可能な技術的基盤；パイロット運用からのエビデンス；中立的な標準を通じた業界へのチャネル；あなたが既に使用している人道支援データ標準との相互運用性。

**それがどのように社会を前進させるか。** 家庭におけるより安全な機械；それがサービスを提供する人々を守る食料救済；都市における廃棄物の削減。

## 9. 資本：投資家、起業家、慈善団体、開発銀行

**Message.** 調理はインフラになろうとしています。標準は無料ですが、その周辺のサービスはビジネスです：certification、hubソフトウェア、同意を得たデータセット、registryの運用、パイロット。人道的なレイヤーは、開発資金提供者が事前登録された評価によって支援できる公共財です。このサイトのどこにおいても、金銭的な約束は行われていません。

**Options.** 機会、ビジネスモデル、ロードマップ、リスク、およびガバナンスを読み取る
(`/investors`) · パイロットまたはレビューに資金を提供 ・ 無料の標準に加えてサービスを販売する企業を支援 ・ 資金提供者オブザーバーとしてガバナンスに参加。

**最初の成功。** ホワイトペーパーのproblem、architecture、risksのセクション、およびaction planのconcern registerを読み込んでください。すべての未解決のriskがリストされています。

**Flow.** エビデンス (pilots, conformance, adopters) → アクションプランにおけるゲート → ゲートに紐付けられた資金提供 → 標準のためのニュートラルな基盤、サービスのための企業。

**それがどのように彼らの仕事を前進させるか。** 正確な数値を用いた、カテゴリーを定義する標準における早期のポジション。公共の利益から切り離された、投資可能なサービス企業。

**それがどのように社会を前進させるか。** 資本は主張されたものではなく、measured なものへと投じられる。

## 10. 考察：哲学者、倫理学者、歴史家、および未来学者

**Message.** 機械が祖母のレシピで料理をするとき、その知識の所有者は誰か？自動化されたケアにおける尊厳とは何を意味するのか？家庭のロボットは何を知り得るのか、そして他に誰がそれを知り得るのか？Cookwalaはこれらの問いに対してコードを通じて選択を行ってきました。エッセイ (`docs/essays/`) はそれらが何であったかを述べ、異議を唱えることを求めています。

**Options.** エッセイを読む · 回答を書く · ルールを提案する (RFCはスキーマを伴う哲学的な議論です) · household context プロファイルの倫理審査に加わる。

**最初の成功。** household data に関するエッセイと facet registry の travel rules を読み、デフォルトを変更したい facet を1つ見つけ、その理由を述べてください。

**フロー。** エッセイ → 公開コメント → RFC → デフォルトの変更。

**それがどのように彼らの業務を前進させるか。** 倫理的な立場が実行中のルールとなり、議論の公開記録が残るライブケース。

**それがどのように社会を前進させるか。** 機械が数百万の家庭に普及する前に、親密なデータと文化的継承に関する決定を公開の場で行う。

## 11. すべての人：食、廃棄物、雇用、気候、そして未来を大切に思う人々

**Message.** Cookwalaは、誰でも、あるいは何でも、安全に料理できるようにレシピを書く方法であり、捨てられるはずの食べ物がそれを必要としている人に届くようにする方法です。それは自由であり、どの企業にも属しておらず、自身が知らないことを明示します。

**Options.** dry run を試す · シミュレーターを再生する · レシピを読む · お気に入りのレシピを1つ書く · ロードマップに従う · food bank または学校にそれを伝える。

**最初の成功。** dry run でデバイスを変更し、ステップが refusal before heat される様子を確認してください。その理由を読み取ってください。

**Flow.** 好奇心 → 1つのレシピ → それを活用できるキッチンとの1つの会話。

**それがどのように彼らの生活を前進させるか。** 家庭内のより安全な機械、自分たちのレシピの保存、お金を渡すことなく助ける方法。

**それがどのように社会を前進させるか。** 廃棄物の削減、より安全な食品、自炊できない人々を助ける機械、そして人間に戻される時間。

---

## 12. 仕事と尊厳、率直に言えば

調理機械は仕事を変化させる。Cookwalaの立場：人間は常に料理ができること。最初の用途は、自分自身で料理ができない人々や、人手が不足しているコミュニティキッチンであること。レシピがどこで調理されても、料理人の名前がレシピに残ること。労働者の声が運営委員会に席を持つこと。新しい役割（recipe engineers、food-robot technicians、certifiers、rule-pack reviewers）が、人数を約束することなく挙げられていること。
