registryは**ポインタのリスト**です：何が存在するか、誰がそれを公開したか、どの正確なバージョンか、
そしてそのハッシュです。コンテンツは、その発行者がホストする場所（あらゆるカタログ、あらゆるドメイン）に留まります。
誰でもregistryを実行できます。cookwala.aiは、`/v1/registry.json`で最初のものを実行しています。

## 1. 名前は誰が公開したかを証明する

すべてのエントリは `<namespace>/<name>` と命名されます。名前空間は証明されなければなりません：

| Namespace | 例 | 証明 |
|---|---|---|
| ドメイン、反転 | `org.fifi-cooking/egyptian-home` | `fifi-cooking.org` 上の DNS TXT レコード `cookwala-verify=<token>`、または `https://fifi-cooking.org/.well-known/cookwala-verify` がトークンを返すこと |
| コードホストのアカウント | `io.github.amado2k5/recipes` | そのアカウント内の CI ジョブからの GitHub (または GitLab) OIDC トークン |
| キー | any | すでに namespace にバインドされているキーによる署名 (rotation) |

名前は決して再利用されません。削除されたエントリはtombstoneとして残ります。

## 2. バージョンは正確です

- **Exact versions only.** エントリは特定のバージョン (`1.4.2`) を固定します。`^1.4` や `1.x` のような範囲指定は拒否されます。
- **Hashes.** 各バージョンはアーティファクトの `sha256` を記録し、クライアントは使用前にそれを検証します。レシピも独自の Cookwala ドキュメントハッシュを保持しており、実行者は不一致を refusal before heat します。
- **Repository id.** エントリは、存在する場合にコードホストの安定した repository id を記録するため、同じ名前で削除・再作成されたリポジトリを検出できます。

## 3. ライフサイクル

`active` → `deprecated` (まだ使用可能、代替品が存在する) → `recalled` (安全ではない。recall feed にも公開され、executors はこれを拒否する) → `deleted` (tombstone)。

## 4. 公開フロー

```bash
# 1. validate locally (same checks the registry runs)
python tools/validate_specs.py
python tools/cookwala_ref.py hash my-collection/recipe.cookwala.json

# 2. prove the namespace once (DNS TXT or /.well-known/cookwala-verify, or CI OIDC)

# 3. publish the entry
curl -X POST https://cookwala.ai/v1/registry/publish \
  -H "Authorization: Bearer $COOKWALA_PUBLISH_TOKEN" \
  -H "Content-Type: application/json" \
  -d @registry-entry.json
```

`POST /v1/registry/validate` と同じ検証を registry が実行します: schema、recipe semantics（operation envelopes、temperatures）、hashes、および namespace proof です。すべての問題は構造化されたリストとして返されるため、CI で表示できます。

> APIは [`api/registry.openapi.yaml`](../api/registry.openapi.yaml) (RFC-0002) に記載されています。
> サービスは later に提供されます。現在は `site/v1/registry.json` への pull request によってエントリが追加されており、そこにはこのリポジトリに存在するものがリストされています。名前とバージョンのルールは `conformance/profiles/registry.json` によってテストされます。

コミュニティ。各エントリには、役割、国、URL、検証記録、および conformance を主張している場合は、公開された `ConformanceReport` のハッシュが含まれます
(`docs/CERTIFICATION.md`)。掲載は、endorsement、certification、またはパートナーシップを示すものではありません。現在、directory には、まだ他に依頼がないため、このサイトの運営者という1つのエントリのみが存在します。
