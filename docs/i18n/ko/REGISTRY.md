registry는 **포인터 목록**입니다: 무엇이 존재하는지, 누가 이를 게시했는지, 정확히 어떤 버전인지,
그리고 그 hash입니다. 콘텐츠는 게시자가 호스팅하는 곳(어떤 catalog, 어떤 domain이든)에 그대로 유지됩니다.
누구나 registry를 운영할 수 있습니다. cookwala.ai는 `/v1/registry.json`에서 첫 번째 registry를 운영합니다.

## 1. 이름은 누가 게시했는지 증명합니다

모든 항목의 이름은 `<namespace>/<name>`입니다. 네임스페이스는 반드시 증명되어야 합니다:

| Namespace | 예시 | 증거 |
|---|---|---|
| 도메인, 역순 | `org.fifi-cooking/egyptian-home` | `fifi-cooking.org`의 DNS TXT 레코드 `cookwala-verify=<token>`, 또는 `https://fifi-cooking.org/.well-known/cookwala-verify`가 해당 토큰을 반환함 |
| 코드 호스트 계정 | `io.github.amado2k5/recipes` | 해당 계정의 CI 작업에서 생성된 GitHub (또는 GitLab) OIDC 토큰 |
| 키 | any | 이미 해당 namespace에 바인딩된 키에 의한 서명 (rotation) |

이름은 절대 재사용되지 않습니다. 삭제된 항목은 tombstone으로 유지됩니다.

## 2. 버전은 정확합니다

- **Exact versions only.** 항목은 특정 버전(`1.4.2`)을 고정하며, `^1.4` 또는 `1.x`와 같은 범위는 거부됩니다.
- **Hashes.** 각 버전은 아티팩트의 `sha256`을 기록하며, 클라이언트는 사용 전에 이를 검증합니다. 레시피 또한 자체 Cookwala 문서 해시를 포함하며, 실행기는 불일치 시 refusal를 수행합니다.
- **Repository id.** 항목은 가능한 경우 코드 호스트의 안정적인 repository id를 기록하므로, 동일한 이름으로 삭제 후 재생성된 repository를 감지할 수 있습니다.

## 3. Lifecycle

`active` → `deprecated` (여전히 사용 가능하며, 대체제가 존재함) → `recalled` (안전하지 않음; recall feed에도 게시되며, executors가 이를 거부함) → `deleted` (tombstone).

## 4. Publishing flow

```bash
# 1. validate locally (same checks the registry runs)
python tools/validate_specs.py
python tools/cookwala_ref.py hash my-collection/recipe.cookwala.json

# 2. prove the namespace once (DNS TXT or /.well-known/cookwala-verify, or CI OIDC)

# 3. publish the entry
curl -X POST https://cookwala.ai/v1/registry/publish \
  -H "Authorization: Bearer $COOKWALA_PUBLISH_TOKEN" \
  -H "Content-Type: application/json" \
  -d @registry-entry.json
```

`registry`는 `POST /v1/registry/validate`와 동일한 검증을 실행합니다: schema, recipe semantics (operation envelopes, temperatures), hashes 및 namespace proof. 모든 문제는 구조화된 리스트로 반환되므로 CI에서 이를 표시할 수 있습니다.

> API는 [`api/registry.openapi.yaml`](../api/registry.openapi.yaml) (RFC-0002)에 기술되어 있습니다.
> 서비스는 later에 제공됩니다; 현재는 `site/v1/registry.json`에 pull request를 통해 항목이 추가되며, 이는
> 이 저장소에 존재하는 것들만 나열합니다. 이름 및 버전 규칙은
> `conformance/profiles/registry.json`에 의해 테스트됩니다.


## 6. 조직 directory

`/v1/directory.json`은 목록에 포함되기를 **요청한** 조직들을 나열합니다
(`catalog.schema.json#/$defs/DirectoryEntry`): 기기 제조사, 카탈로그, registries, food banks,
커뮤니티 주방, 학교 및 구호 프로그램, 농장 및 협동조합, 식료품점, 레스토랑,
레시피 발행사, certifiers, 연구소, 보건 기구, 정부, 보험사, 번역가
커뮤니티. 각 항목은 역할, 국가, URL, 검증 기록을 가지며, conformance를 주장하는 경우,
발행된 `ConformanceReport`의 해시값을 가집니다
(`docs/CERTIFICATION.md`). 목록 등재는 보증, certification 또는 파트너십이 아닙니다. 현재
directory에는 이 사이트의 운영자라는 하나의 항목만 있는데, 이는 아직 다른 누구도 요청하지 않았기 때문입니다.
