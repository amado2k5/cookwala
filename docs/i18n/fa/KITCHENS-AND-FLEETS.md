# آشپزخانه‌ها و دوره‌های تولید: رستوران‌ها، جامعه، مدرسه، بلایا و آشپزخانه‌های رباتیک

> **وضعیت: experimental profile** (RFC-0005). Schema: `schemas/fleet.schema.json`.
> نمونه‌ها: `examples/fleet/`.

## ۱. چرا

بنیان‌گذار همان پروتکل را در یک رستوران، یک عروسی، یک کمپین اهدای غذا یا یک کارخانه مواد غذایی درخواست کرد (RFC-0005). این خلاصه، برنامه‌های وعده‌های غذایی مدارس و آشپزخانه‌های مدیریت بحران را نیز اضافه می‌کند. بخش Core شامل پخت یک دستور پخت توسط یک دستگاه است؛ Humanitarian Profile جابجایی surplus و شمارش وعده‌های غذایی را پوشش می‌دهد. بین آن‌ها **kitchen** قرار دارد: ایستگاه‌ها، دستگاه‌ها، افراد، دسته‌های متعدد، یک بازه زمانی سرو، نقاط کنترل بحرانی، و پیوند میان execution log یک دستگاه با وعده‌های غذایی که یک برنامه گزارش می‌دهد.

## 2. اسناد

| سند | آنچه می‌گوید |
|---|---|
| `Kitchen` | آشپزخانه یک سازمان: نوع، ایستگاه‌ها (آماده‌سازی، اجاق، فر، سرخ‌کن، کتری، سلول رباتیک، بشقاب‌گذاری، بسته‌بندی، نگهداری گرم، خنک‌سازی، انبار سرد، شستشو)، دستگاه‌ها به عنوان مراجع قابلیت، ظرفیت بر حسب وعده‌های غذایی در ساعت، تجهیزات نگهداری گرم و خنک‌سازی، rule packs در حال اجرا، **تعداد کارکنان بر اساس نقش**، ساعات کاری |
| `ProductionRun` | دستورهای پخت با تعداد دسته‌ها و وعده‌ها، یک بازه زمانی سرو، انتساب‌های هر مرحله دستور پخت به یک ایستگاه و به یک `device` یا یک `person` یا هر دو، سوابق نقاط کنترل بحرانی (دمای هسته پخت، نگهداری گرم، خنک‌سازی دو مرحله‌ای، گرم کردن مجدد، ذخیره‌سازی خنک، جداسازی آلرژن)، Core executions تولید شده، و یک نتیجه (وعده‌های غذایی تولید و سرو شده، ضایعات، غذای نجات‌یافته استفاده شده، شکست‌ها، حوادث، انرژی، هزینه، Humanitarian `Distribution` منتشر شده توسط آن) |
| `StationLease` | استفاده انحصاری از یک ایستگاه توسط یک device یا یک نقش برای یک بازه زمانی |

## ۳. چگونه به بقیه متصل می‌شود

- یک مرحله اختصاص یافته به یک `device` یک Core `ExecuteRequest` (یا یک هدف `ExecuteNode` از طریق ROS 2 binding) است؛ هش `ExecutionLog` آن در `executions` قرار می‌گیرد.
- یک run که به یک برنامه خدمت می‌کند، یک Humanitarian `Distribution` صادر می‌کند؛ `ccps` مربوط به run، شواهد پشت یافته‌های ایمنیِ distribution هستند.
- rule packهای حاصل از Humanitarian Profile برای منو و اقلامِ run اعمال می‌شوند.
- اعزام ناوگان (اینکه کدام ربات به کجا می‌رود) متعلق به Open-RMF یا مدیر ناوگان یک فروشنده است، نه متعلق به این profile.

## 4. مثال حل شده

`examples/fleet/kitchen-disaster.json` و `production-run-disaster.json`: یک آشپزخانه امدادی
با دو کتری گازی، واحدهای نگهداری گرم (hot-hold units) و یک حمام یخ، ۷۱۰ وعده سوپ عدس و
برنج را برای یک بازه زمانی دو ساعته تولید می‌کند، دماهای پخت و نگهداری گرم را ثبت می‌کند، یک واحد نگهداری گرم را
زیر ۶۰ °C پیدا کرده و آن دسته را قبل از سرو مجدداً گرم می‌کند، و یک توزیع صادر می‌کند. این مثال
توضیحی است؛ هیچ آشپزخانه یا رویداد واقعی توصیف نشده است.

## ۵. آنچه عامدانه حذف شده است

نام‌ها و برنامه‌های زمانی کارکنان، دستمزدها، سفارش‌ها و پرداخت‌های مشتریان، قیمت‌گذاری منو. کارکنان به صورت تعداد بر اساس نقش ظاهر می‌شوند تا هزینه هر وعده غذایی بدون شناسایی افراد قابل محاسبه باشد.
