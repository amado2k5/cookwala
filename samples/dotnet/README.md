# Cookwala samples for .NET

Sample clients, agents, orchestrators, gates, recovery and reporting for the Cookwala Core 0.2 API,
for .NET 8 and later. Everything runs offline against simulated devices built from a bundled snapshot
of the Cookwala repository, or against a real hub (`python hub/cookwala_hub.py`, or any executor
that serves the Core API). No dependencies beyond the BCL (System.Text.Json, HttpClient, HttpListener).

**Status:** Samples, not certified software; simulated devices; the executor is always the authority.

This is a port of the Python reference package (`samples/python`). The cross-language contract,
including the demo every port reproduces, is in `samples/SPEC.md`.

## Install

Library:

```sh
dotnet add package Cookwala.Samples
```

Command line (a .NET tool):

```sh
dotnet tool install -g Cookwala.Samples.Tool
cookwala-samples demo                      # Markdown report of the six demo jobs
cookwala-samples demo --format junit --out demo.xml
cookwala-samples demo --hub http://127.0.0.1:7878 --token T   # the fault-free jobs against a hub
cookwala-samples gates shakshuka --block eggs
cookwala-samples plan koshari --human-present
cookwala-samples run lentil koshari --human-present --fault example-koshari#n14=overheat
cookwala-samples serve --port 8080         # GET /v1/samples, POST /v1/samples/gates|plan|run
cookwala-samples list
cookwala-samples version
```

Exit codes: 0 ok; 1 a gate refused, a plan failed, or a run did not complete; 2 usage.

## Library example

```csharp
using System;
using System.Text.Json.Nodes;
using Cookwala.Samples;

// The whole demo: four simulated devices, a planner agent, a person, six orders.
Reporter rep = Scenarios.Demo();
Console.Write(rep.ToMarkdown());

// One order through the gates, the device ranking, the executor and recovery.
var human = new ScriptedHuman(present: true);
var mandate = Mandates.Make("household:h-1/person:p-1", "agent:planner");
var planner = new PlannerAgent("agent:planner", mandate, new BundleCatalog(), human);
var orch = new Orchestrator(Scenarios.Kitchen(), planner: planner, human: human, recalls: new JsonObject[0]);
RunRecord run = await orch.RunAsync(new Job("dinner", order: new JsonObject { ["dish"] = "lentil", ["servings"] = 4 }, humanPresent: true));
Console.WriteLine($"{run.Outcome} on {run.Device}: {run.Disposition}");

// The same orchestrator over HTTP: swap the kitchen for a hub client.
var hub = new HubClient("http://127.0.0.1:7878", token: "T");
var catalog = await HubCatalog.CreateAsync(hub);
```

## The six roles

| Role | Types | What it does |
|---|---|---|
| Clients | `IExecutorClient`, `HubClient`, `LocalClient`, `BundleCatalog`, `HubCatalog` | one interface over HTTP and over the in-process `SimulatedExecutor`; HTTP retries reuse the Idempotency-Key |
| Gates | `GatePipeline.Default()`, `GateContext`, `GateDecision` | core-version, recipe-hash, recall, mandate, allergen, untrusted-text, envelope, attendance, capability; fail closed; untrusted text is logged, never obeyed |
| Agents | `PlannerAgent`, `MonitorAgent`, `ScriptedHuman`, `Mandates.Make` | a planner that acts only under a mandate and never substitutes around an allergen block; a monitor that checks transitions, sequence and temperatures |
| Recovery | `RecoveryPolicy`, `RecoveryAction` | never retry around safety; try the next device; ask a person; nobody answering means stop; discard and report after heat |
| Orchestrator | `Orchestrator`, `Job` | planner → gates → rank devices by dry run → start → poll, monitor, recover → log → incident |
| Reporting | `Reporter`, `RunRecord`, `Incidents.IncidentFrom` | JSON (same field names as the Python reference), Markdown, JUnit XML, CSV; anonymous IncidentReports |

Underneath: `Jcs` (RFC 8785 canonical JSON and the document hash), `Simulator` (the dry run and the
simulated executor), `Bundle` (the embedded data) and `Service` (the HTTP handler behind `serve`).

## Build and test

```sh
cd samples/dotnet
dotnet test
dotnet run --project src/Cookwala.Samples.Cli -- demo
dotnet pack -c Release -o out
```

`nuget.config` lists nuget.org as the only source. The shared data (`samples/data/bundle.json`,
generated by `samples/tools/build_bundle.py`) is embedded in the library at build time.

## Publishing

Both packages (`Cookwala.Samples` and `Cookwala.Samples.Tool`) are built by `dotnet pack`. The
publisher adds the release feed (Artifactory or GitHub Packages) at release time:

```sh
dotnet pack -c Release -o out
dotnet nuget push out/*.nupkg --source <artifactory-nuget-url> --api-key <key>
# or GitHub Packages:
dotnet nuget push out/*.nupkg --source https://nuget.pkg.github.com/<owner>/index.json --api-key <token>
```
