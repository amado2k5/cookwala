# Independent-style review of cookwala.ai and the Cookwala standard

**Date:** 2026-10-04. **Subject:** https://cookwala.ai and `amado2k5/cookwala` at commit `93f5a2e`
(`main` = `cookwala-v2`). **Reviewer:** Claude (Fable 5.1) running `prompts/critique-prompt.md`
on the founder's request; this is not a review by an outside organisation and must not be listed
as one. **Method:** live site read in a browser (desktop and 375 px, light and dark), axe-core
4.10.2 injected per page, keyboard sessions, curl for headers and sizes; repository read and
executed with `.venv-cw/bin/python`; the reference hub run locally and probed with curl; attack
scripts kept outside the repo. Baseline before the review: `validate_specs.py` ok,
`run_conformance.py` 106/106, `scenarios/run.py` 100/100. Every finding below names the command
or page that produced it. Things that could not be verified are listed at the end.

Severity: **blocker** = the central claim or a legal position fails; **high** = a reader or
implementer is misled or an attack works; **medium** = the standard is ambiguous or the site is
wrong in a way a careful reader notices; **low** = polish.

## Ranked findings

### Blockers

**1. Blocker. Revocation is defeated by editing an unsigned timestamp.**
`tools/cookwala_ref.py:99-101` (`doc_hash` excludes `signature`) and `:121-124` (`verify` reads
`sig['signedAt']`). `signedAt` lives inside the excluded `signature` object, so it is not covered
by the signature. Run: vector `sig-revoked-key` as shipped → `(False, 'key_revoked')`; the same
document with `signedAt` rewritten to `2026-08-01` → `(True, 'ok')`. Anyone holding a leaked,
later-revoked catalog key backdates every forgery, including recalls, and passes every vector.
Audience: catalogs, verifiers, regulators. Fix: sign over the canonical form of
`{hash, kid, alg, signedAt}` (a protected header), make `signedAt` required, and add a vector
whose backdated signature must fail.

**2. Blocker. Chain and checkpoint verification skips revocation and ignores validity windows.**
`tools/cookwala_ref.py:163-171` (`_verify_hash`): revocation is checked only `if
sig.get('signedAt')`; `validFrom`, `validTo` and `alg` are never checked. Runs: a chain whose
sequencer key was revoked, `signedAt` stripped → `(True, 'ok')`; the shipped checkpoint (no
`signedAt`) verified against a revoked key → `(True, 'ok')`; keys with `validFrom` 2030 →
`(True, 'ok')`. `docs/CORE.md:88-90` promises the opposite; `key_not_valid_at_signing_time`
appears in no vector. Audience: anyone relying on witnessed checkpoints. Fix: one verification
function for documents, events and checkpoints that enforces alg, window and revocation and
refuses signatures without a signing time.

**3. Blocker. 1,547 recipes are published under a licence that grants nothing, from sources the
project itself says are not cleared.** `recipes/INDEX.json`: `LicenseRef-source-credited` 1,547,
`CC-BY-4.0` 334. `tools/export_fifi.collections.json`: osool and abdennour "book rights not
cleared", abuhaty "creator permission to be confirmed", chefteta "licence to be confirmed".
`docs/EXPORT-FIFI.md:45-55` recommends "exclude, or publish only a structured V0 card" for two of
them. Yet every document carries the source steps verbatim in `text.ar.legacySteps` (difflib
ratio 1.00 against `fifirecipes/public/data/recipes/<id>.json` for osool-409, ec-337, fah-463)
and is served at `https://cookwala.ai/v1/recipes/<id>.cookwala.json` (200) and `/recipes/<id>/`
("Licence: credited; licence under review"). `LicenseRef-source-credited` is defined nowhere in
the repo (mentioned only at `rfcs/0009:30`); an undefined LicenseRef conveys no right to
redistribute. Audience: the founder (liability), every downstream user (82 % of the index is
unusable). Fix: set `export: false` for the four collections until rights are in writing, or
publish ingredients and metadata only with a written LicenseRef text.

**4. Blocker. A "certified" conformance report can be forged and validates.**
`.venv-cw/bin/python tools/run_conformance.py --report r.json` writes keys `claim, core, date,
hash, id, kind, profile, status, subject, suites, tool, vectorsHash` and **no `signature`**;
`examples/conformance/report-reference.json` likewise. `docs/CERTIFICATION.md:10` says a
self-declared report is "signed with its own key". A report edited to `status: certified`,
`verifier: "Totally Independent Certifier Ltd"`, all passed, `vectorsHash: sha256:aaaa…`
validates against `schemas/conformance.schema.json` with zero errors. Nothing binds
`vectorsHash` to the committed vectors or requires the verifier to exist. Audience: device
makers, buyers, insurers. Fix: require `signature` for every status, publish the canonical
`vectorsHash` per tool commit, and make `verifier` an organisation id resolvable in the directory.

**5. Blocker. The reference hub ignores authentication; any client on the network can start a
cook.** `api/core.openapi.yaml:24` `security: - bearer: []`; `grep -ci authorization
hub/cookwala_hub.py` → 0; `hub/README.md` admits "accepting any bearer token". `POST
/v1/executions` with no `Authorization` header → `202 Accepted`. CORS is `*` on every response
(`hub/cookwala_hub.py:212,227`), so any web page on the LAN can do the same. Audience: device
makers who copy the reference. Fix: return 401 on a missing or invalid bearer, add a pairing
stub, restrict CORS, or label the hub an auth-less test bed in the spec's `servers` block.

**6. Blocker. "Refusal before heat" never looks at the recipe's temperatures.**
`tools/cookwala_ref.py:300-330` (`dry_run`) checks op membership, `unattended` and the ladder
only. Run: koshari with the deep-fry node set to `oilTempC: 260`, `target.value: 260`,
`tempC: 260` against `demo-fryer-robot.json`, person present → `accepted`, no refusal. The hub's
`start()` calls the same function and compares only the hash, so a validly hashed recipe with an
out-of-envelope target is accepted for cooking. The only envelope check is in
`tools/validate_specs.py:122-132`, publisher-side, run on `examples/` only, and it raises
`TypeError` on a string temperature. `SafetyLimits` is loaded by the hub but never consulted in
`start` or `dry_run`. Audience: cooks, device makers, regulators. Fix: an executor-side check of
every target, heat level and `oilTempC` against the envelope and the local limits inside
`dry_run`, with vectors `dryrun-target-outside-envelope → refused` and
`dryrun-exceeds-safety-limit → refused`.

**7. Blocker. The hub's allergen block never matches a real allergen.**
`hub/cookwala_hub.py:83` `set(recipe['safety']['allergens'])`; the field is an object
(`{'eu14': [...], 'us9': [...], 'mayContain': []}`), so the set is `{'eu14','us9','mayContain'}`.
Shakshuka (eggs) with `allergenBlocks: ["eggs"]` → `accepted`; `allergenBlocks: ["eu14"]` →
`refused allergen_block`. Core rule 7 (`docs/CORE.md:127`) is non-functional in the only
executor, and no scenario sends `allergenBlocks` on an ExecuteRequest. Audience: a cook with an
allergy. Fix: flatten `eu14`, `us9`, `mayContain` and ingredient-level allergens, and add the
scenario "blocked allergen refuses".

### High

**8. High. Key id and algorithm are not bound into the signed bytes; event attribution is
mutable.** The signature covers only the ASCII hash (`tools/cookwala_ref.py:112`,
`docs/CORE.md:86`). Registering the same public key under another `kid` and rewriting `kid` →
`(True, 'ok')`. `event_hash` (`:135`) excludes `proposedBy`; changing it on a signed event leaves
`verify_chain` at `(True, 'ok')`. There is no domain separation between recipes, events,
checkpoints, mandates and recalls. Fix: include a context string, `kid` and `alg` in the signed
message and hash `proposedBy`, or document it as unsigned metadata.

**9. High. Witnessed checkpoints prove nothing in the reference.** `tools/cookwala_ref.py:183-191`
accepts zero witnesses, accepts the sequencer witnessing itself, has no minimum or independence
rule, and nothing compares two checkpoints at the same `seq` with different heads.
`docs/CORE.md:99` "the chain never forks" is asserted, not mechanised; `ledger-rewrite-detected`
tests only a rewrite against one held checkpoint. Fix: require at least one witness whose `kid`
differs from the sequencer's and add a fork vector (`fork_detected`).

**10. High. Selective-disclosure digests over small value spaces are brute-forceable, and the
salt rule is unenforced in code.** `common.schema.json` demands `minLength: 22` on the salt;
`verify_disclosure` (`tools/cookwala_ref.py:131`) accepts a one-character salt. With a
schema-valid constant salt, `halal` is recovered from a six-value list in microseconds.
`docs/HOUSEHOLD-CONTEXT.md` never mentions salt, reuse or enumeration. Audience: households
disclosing religion, allergy or diet. Fix: normative text "salt MUST be at least 128 bits of
fresh CSPRNG output per value and never reused", verifier rejection below 22 characters, and a
vector.

**11. High. Sensor-ladder rungs `model` and `time` are satisfiable by any device, so
`missing_sensor_no_fallback` is unreachable except for deep frying and knife work.**
`tools/cookwala_ref.py:285-292`: `model` passes when the caller's `allow_model` flag is true (not
a device capability); `time` always passes. A device with `sensors: []`, nobody home: simmer,
bake, cool and hold → `accepted` with rung `model`; with `--no-model` → `accepted` with rung
`time`. `cw.op.cool`, a critical control point by its own note, is "verified" by a clock. Fix:
`model` requires a declared `models: [op]` capability with logged accuracy; `time` is disallowed
for ops carrying `cw.hz.time_temperature`.

**12. High. Capability claims are self-asserted and vision cues count as sensors.**
`tools/cookwala_ref.py:308-310` adds `visionCues` to the sensor set. A hob robot listing
`cw.sense.oil_temp` as a cue of its camera plus `cw.op.deep_fry` → koshari `accepted`, deep-fry
rung `cw.sense.oil_temp`. `capabilities.schema.json` does not constrain which cue ids a camera
may claim and carries no maximum heat or temperature; `presenceDetection` is a bare boolean.
Fix: a cue vocabulary that excludes thermal sensor ids, and capability documents signed by the
maker and checked against the registry.

**13. High. V0 imported recipes and `cw.op.legacy_step` can reach a device.** RFC-0009 §1 "a
described recipe, never an executable one"; §2 says the op is added "with `executable: false`",
but `vocab/ops.json` has no such field. Runs: `ref.dry_run(osool-409, demo-oven, human_present=True)`
→ `state: accepted` with a five-node plan of `cw.op.legacy_step` "by: human"; the hub advanced
the same recipe to `needs_human` seq 3. `capabilities.schema.json` accepts a device declaring
`cw.op.legacy_step`; the dry run of `recipes/archive/salad-08` on such a device with nobody
present → `accepted`, every step `by: device, verifiedBy: time`. Without a person the refusal
reason is `missing_capability`, not a V0 reason. Fix: `executable: false` in the vocabulary, a
schema `not` on `cw.op.legacy_step` in capabilities, and an `unverified_recipe` refusal for
`verification.level: V0` independent of presence.

**14. High. "A person is present" is a request flag.** `hub/cookwala_hub.py:329`
`human = bool(req.get('x-hub-human-present'))`; `sdk/python/cookwala/client.py:98` sets it. It
is unsigned, unverified against `presenceDetection`, absent from `ExecutionLog`, and any agent
may assert it: a request with `requestedBy: agent:evil`, no mandate, flag true → `accepted`.
`docs/CORE.md:125-126` "present, or reachable within one minute" has no observable. Audience:
everyone the standard says it protects. Fix: presence is a device-sensed, signed fact recorded
in the log; a request may only ask for unattended mode.

**15. High. Agent mandates are optional, unsigned, unexpired and replayable.**
`AgentMandate.signature` is not in `required` (`schemas/common.schema.json`); the hub checks
`scopes` only if a mandate is present (`hub/cookwala_hub.py:81`). Observed: mandate `expires:
2020`, unsigned → `accepted`; agent request with no mandate → `accepted`; identical request under
a new `id` → `accepted`. Scenario 048's "passing" mandate is unsigned. Fix: require and verify
the signature, check `expires`, bind the mandate hash and a nonce into the request.

**16. High. The reference hub does not conform to its own Core API.** Status documents from
`GET /v1/executions/{id}` fail `core.schema.json#/$defs/ExecutionStatus` (`'request' is a
required property`; `plan`, `recipe`, `recipeHash` unevaluated). `refusal` is an object in
ExecutionStatus and a string in the Problem document (`api/core.openapi.yaml:216-228`; observed
`"refusal": "unsupported_version"`). `ETag: 0` is unquoted (RFC 9110 requires `"0"`); a
spec-correct `If-Match: "0"` → 412; a missing header → 428, which is not in the spec.
`POST …/stop` without `Idempotency-Key` → 400 (`hub/cookwala_hub.py:319-320`), although
`docs/CORE.md:113` says stop is never refused. Problem `type` URIs such as
`https://cookwala.ai/errors/precondition-failed` return 404. `/v1/incidents` accepts `not json`
with `{"received": true}`. Audience: anyone writing a client from the spec. Fix: a wire-level
conformance suite that drives the Core API and fails on each of these.

**17. High. Idempotency replay ignores the body and is global.** Same `Idempotency-Key`,
different body (new id, other recipe) → the original status, 202. The store is `self.idem = {}`
(`hub/cookwala_hub.py:54`), never expires, and with no authentication any caller's key replays
any other caller's status. The spec (`api/core.openapi.yaml:14`) defines no mismatch behaviour.
Fix: hash the body with the key, return 422 on mismatch, scope keys per principal, define a TTL.

**18. High. The executor class is document tests only; nothing touches a device.** Vectors: hash
4, signature 9, disclosure 2, ledger 4, units 5, envelope 14, transitions 11, profiles 68. None
sends an HTTP request, measures stop latency or checks limits without a network;
`docs/CERTIFICATION.md §3` lists these as "also needed", not tested. The hub's own
`/v1/conformance` answers `report: None`. Audience: device makers, buyers. Fix: a wire suite and
a hardware checklist schema with measured values, before any "executor" claim is accepted.

**19. High. "Verified" is self-verification and the registry's own namespace proof was never
performed.** `docs/CERTIFICATION.md §1` admits the only registry operator is the maintainer.
`site/v1/registry.json` lists only `ai.cookwala/*` entries, each with `verification.method:
dns_txt … by: cookwala.ai`; `dig TXT cookwala.ai` returns nothing and `/.well-known/cookwala-verify`
→ 404. `/v1/registry/validate` and `/publish` → 404 although `api/registry.openapi.yaml`
describes them. The directory has one entry: the operator. Fix: remove verification records
that were not performed and label the registry "static, maintained by pull request".

**20. High. The patent pledge binds nobody identifiable.** `PATENTS.md`: "fifi.cooking and every
contributor who signs the contribution agreement"; no contribution agreement, CLA or DCO exists
(`CONTRIBUTING.md:35` is a bare "by contributing you agree"). "fifi.cooking" is a website, not
a legal person; no signatory, date or transfer clause; the footer says "Draft. Have it reviewed
by counsel". Audience: implementers, a future foundation. Fix: name the legal person, add a DCO
line carrying the pledge, add a clause binding transferees.

**21. High. The RFC process has not run once and nobody can say no to the editor.**
`rfcs/README.md`: nine RFCs, all proposed or draft, comment-period column empty ("opens when
the PR merges"); PR amado2k5/cookwala#1 merged 2026-10-04 and no window date was written;
`gh issue list` → zero issues; `git shortlog` → one author, 30 commits over two days; no RFC
rejected, no decision record, no comment by anyone else. `GOVERNANCE.md:12` points to
`docs/DECISIONS.md`, which is the Mission "Decisions, Commitments, Budgets" profile, not a
decision log. "Maintainers" appear in no file. Fix: write open and close dates into every RFC
header now, create a real decision log, and name an interim second approver in writing.

**22. High. The site claims 25 languages; six are live.** `/ja/`, `/hi/`, `/ru/`, `/zh/`,
`/it/`, `/fa/`, `/ur/`, `/he/`, `/ps/` all return 404; `tools/build_site.py:43,188-193` builds
a language only when `site/content/<lang>/strings.json` exists (en, ar, de, es, fr, pt).
`docs/i18n/` holds 24 language folders built nowhere. `site/content/en/deck.html:11` says both
"the site in 25 languages" and "a site in English and Arabic" on one slide; `roadmap.html:18`
"The site and documentation in 25 languages". The sitemap has 1,890 English and 1,890 Arabic
recipe pages and none in the other four live languages. Fix: one sentence everywhere, "site in
6 languages, recipe names in 25, core documents machine-translated in 24 and not yet published",
and either build or delete the unpublished translations.

**23. High. Numbers and units render reversed in the Arabic normative spec.**
`https://cookwala.ai/ar/docs/CORE/` section 3: "85–96 °C" paints as "C° 96–85", "160–190 °C" as
"C° 190–160", "0.5 s" as "s 0.5" (screenshot). Five of five numeric runs in `<main>` are outside
any `<bdi>`, `dir="ltr"` or `<code>`; the only isolation is `site.css:134` for `code`. The same
applies to the Arabic whitepaper and 1,890 Arabic recipe pages. Audience: Arabic food-safety
readers of a safety spec. Fix: wrap numeric value-plus-unit runs in `<bdi dir="ltr">` in
`tools/md.py` and the recipe renderer.

**24. High. Recipe hreflang clusters are broken.** `/recipes/add-001/` declares
`hreflang="fr" href="https://cookwala.ai/fr/recipes/view/?id=add-001"`, a JavaScript shell whose
canonical is `/fr/recipes/view/` with the id dropped. Non-reciprocal alternates are ignored, so
no French, Spanish, German or Portuguese recipe page can index, and the English page advertises
alternates that do not exist. The sitemap (4,746 URLs, 282 KB) has no `lastmod` and no hreflang;
Arabic recipe text is itself labelled machine-produced, so 1,890 thin pages compete with 1,890
English ones. Fix: emit hreflang only for languages with a static page, add `lastmod`, and
consider `noindex` on machine-translated V0 pages.

**25. High. Contrast failures on the elements the site exists to show.** axe on `/` (light):
`color-contrast`, 24 nodes, `#ffffff` on `#d9481c` = 4.29 (`site/assets/site.css:5`, every
`.btn.primary`). Dark mode on `/` and `/playground/`: the verdict tags "ACCEPTED" `#fff` on
`#4cc38a` = 2.21 and "REFUSED" on `#f2867d` similar (`site.css:12,146-147`). Fix: darken
light-mode ember to about `#c43f16` and set `color: var(--paper)` on tags in dark mode.

**26. High. In the deck, Enter on "Previous" goes forward.** `/deck/#4`, focus `#prev`, press
Enter → counter "5 / 14". `site/assets/deck.js:15-17` intercepts Enter and space on `document`
and calls `show(i+1)` with `preventDefault`, so the button never fires. After arrow navigation
`document.activeElement` is `BODY` (`deck.js:11` sets tabindex but never calls `focus()`).
Audience: keyboard and switch users. Fix: ignore the global handler when the target is a button
and call `slides[i].focus({preventScroll: true})`.

**27. High. Evidence labels are wrong where they matter most.**
`site/content/en/investors.html:30` renders "measured 1,890 example recipes, two languages":
9 are examples, 1,881 are V0 imports, text exists in 25 languages. `tools/site_stats.py:44,46`
hardcode `sdkLanguages: 13` and `languages: 25` under a "measured" label on a page that says
"Counted from the repository at each build"; `/developers/` lists "JavaScript", for which no
SDK folder exists. `site/templates/diagrams/health.svg` prints "measured · WHO, Codex, Sphere"
under rule packs that the pack file itself says are "not reviewed by the source bodies"; the
`goals.health_problem` string puts a "measured · WHO" chip after an unsourced salt opinion.
`impact.html:21` says 770 million "rounds up" 733 million (a 5 % change); `impact.html:32`
quotes "9 to 12 g" salt where the current WHO page says 11 g (2021). Audience: investors,
public-health readers. Fix: count every tile from the repository, remove "measured" from any
derived or editorial statement, and correct the investors tile and the two WHO figures.

**28. High. The food-bank "first success" cannot be done as written.** `site/content/for.json`
(humanitarian, "first"): "Fill the three CSV templates for one day, then compute the summary:
`cookwala humanitarian --summary your-folder …`". `grep -i csv tools/humanitarian_check.py` →
nothing; the tool reads JSON documents; there are four templates, not three. The command does
work on the example folder (`kgRescued 128 measured n=2 · mealsServed 380`). Audience: the one
audience the hunger goal depends on. Fix: add CSV ingestion or point the first success at the
example folder and say "JSON documents".

**29. High. Translation provenance is misstated.** `/ar/docs/CORE/` carries the notice "this
page was machine-translated and not yet reviewed", with "فئات conformance" and untranslated
table rows, while the deck and roadmap say Arabic is by people. `site/content/fr/humanitarian.html:14,15,19,31`
contain whole English paragraphs on a page declared `lang="fr"`; `/fr/goals/` and `/de/goals/`
have English titles (`tools/build_site.py:303`). The French CORE renders "l'envelope, la
ladder" and keeps "recall" where the regulatory term is "rappel". Fix: state per page who
translated it, fail the build when a shipped fragment contains untranslated English sentences,
and have a French speaker fix the safety vocabulary.

**30. High. "No tracking" is not true as deployed.** `/trust/` says "No analytics, no cookies,
no tracking on this site", yet every page loads Cloudflare Web Analytics
(`static.cloudflareinsights.com/beacon.min.js`, `POST /cdn-cgi/rum`, injected at the edge, not
in the served HTML) and fonts from `fonts.googleapis.com` (`site/templates/layout.html:22`),
which sends visitor IPs to Google. Audience: everyone the privacy section addresses. Fix: turn
off the beacon or disclose it, and self-host the three font faces.

### Medium

**31. Medium. The "normative" document is almost entirely non-normative under its own rule.**
`docs/CORE.md` contains four MUST sentences (lines 36, 49, 59, 65), one MUST NOT (36), and no
SHOULD or MAY outside the RFC 2119 declaration. Section 6 "(normative)" uses lower-case
"never", "always" and "need" eleven times. MUSTs without an executor-side vector: line 36 (cannot
be tested as written); line 49 (checked only publisher-side, see finding 6); line 59 (reachable
only for deep fry and knife ops, finding 11); line 65 (envelope, equipment and safety-limit
refusals have no vector). Lower-case rules with no vector: stop latency, events never protect,
untrusted text, mandate signature and expiry, presence, allergen block, recalls
(`recipe_recalled` in no scenario), incident anonymity, key validity window, hash-only mode,
fork detection, `unsupported_version`. Fix: rewrite each rule in sections 3 to 9 with a keyword
and a vector id, and list the rules that are deliberately untestable.

**32. Medium. The canonicaliser diverges from ECMAScript number formatting.** Python vs
`node`: `1e-6` → `1e-6` vs `0.000001`; `123456789012345680000.0` → `…683968` vs `…680000`;
integers beyond 2^53 are emitted verbatim where I-JSON forbids them. A TypeScript verifier
hashes such documents differently, giving two "valid" hashes for one document. The three
shipped hash vectors exercise none of these; `tools/make_conformance.py:45-46` generates the
expected hashes with the implementation under test. Fix: implement `Number::toString`
(shortest round-trip, decimal between 1e-7 and 1e21), reject integers beyond 2^53, add vectors
for each case computed by a second implementation.

**33. Medium. No `format` is enforced anywhere.** `format_checker` is absent from
`validate_specs.py`, `run_conformance.py` and the hub; `rfc3339-validator` is not installed. A
KeyRecord with `validFrom: "yesterday"` validates with zero errors and then raises `ValueError`
in `_time`; a naive `signedAt` against an aware `validFrom` raises `TypeError`, which in the hub
is a 500, not a refusal. Fix: install format validators, pass a FormatChecker everywhere, and
map time-parsing errors to `invalid_timestamp`.

**34. Medium. Envelopes are unsourced and internally inconsistent.** `vocab/ops.json` has no
`source`, `cite` or `review` key on any envelope; `testMethod` points to `conformance/ops/*.json`,
a directory that does not exist. `cw.op.hold` is defined as "≥ 57 °C typical" with an envelope
minimum of 60; `cw.op.cool` describes 60→21→5 °C staging but encodes a flat −1..60 band with a
`time` fallback; `pressure_cook` has a `time` fallback and no venting rule; `smoke` 90–135 °C
air with `time` fallback and no core-temperature requirement; deep-fry `oilTempC.maximum: 200`
vs envelope max 190; `heat: max` (pan 240–280 °C) is schema-valid on `cw.op.saute` (150–210).
Altitude shifts only water and steam, accepts −9,000 m and 30,000 m, and is applied by the
checker but not the validator. The safety-limits default pack says no authority reviewed it. No
reviewer of record exists. Fix: a `source` object per envelope (document, section, year,
reviewer or "unsourced"), one parameter-to-envelope mapping per op enforced in validator and
executor, and clamped altitude.

**35. Medium. The ingredient and unit vocabularies cannot do what Core relies on.**
`vocab/ingredients.json`: 3,953 entries with only `id, label, classes, definition`; zero
densities (yet `docs/CORE.md:77` names the vocabulary as a density source), zero allergens,
zero synonyms, zero links to FoodOn, FDC or LanguaL; normalised labels collide in 188 groups
covering 527 entries (`onion` ×30, `tomato` ×12); `cw.ing.peanuts` is classed `other`,
`cw.ing.walnuts` and `cw.ing.sesame` `sweet_fruit`, `cw.ing.tahini` `dairy_fat`.
`vocab/units.json` lists eight units; `convert(1, 'oz', 'oz')` passes silently and
`pinch → tsp` asks for a density; CORE says kitchen units are "exact" while the file says
"About 0.36 g". Two implementers can validate the same fragment (`heat: very_low` on sauté,
`attention: none` against an envelope demanding `continuous`, `minTime > maxTime`) and cook it
differently. Fix: one canonical entry per food with preparation modifiers in the ingredient
line, FoodOn ids, allergen and density fields, every `Unit` enum member in `units.json`, and
validator rules for heat within envelope, attention at least the envelope's, and `minTime ≤
maxTime`.

**36. Medium. Headline counts blend draft profiles into "conformance" and disagree with the
tools.** `run_conformance.py:87` concatenates profile suites, so the "106 vectors" on the home

**37. Medium. Versioning and deprecation have policy but no mechanism.** All 24 schema `$id`s
are `https://cookwala.ai/v1/schemas/<name>.schema.json` with no version; Core is "0.2.x";

**38. Medium. The HXL, GS1 and DHIS2 mappings are thin and partly wrong.** The only GTIN in

## What would make me trust this standard

A signature scheme that covers what it claims to cover, verified by one function that every
path uses, with vectors written by a second implementation that fail when revocation, validity
windows, witness independence and backdating are broken. An executor-side dry run that reads
the recipe's temperatures, heat levels and parameters against the envelope and the local limits,
and a wire suite that drives the Core API on a real endpoint and measures a stop. Envelopes with
a named source and a named reviewer, or the word "unsourced" beside them. A presence fact that a
device senses and signs rather than a flag a client sends. A conformance report that cannot be
written without a key and cannot claim a verifier that does not exist. A recipe corpus whose
every document carries a licence the project can point to in writing. And one person other than
the editor who has, in public, said no to something and been recorded doing so.

## What would make me leave the site

Landing on a recipe page from search and finding no sentence about what the page is, who made
it, or what I can do with it. Reading "No analytics, no cookies, no tracking" while the network
tab shows a Cloudflare beacon and Google Fonts. Opening the Arabic specification and reading
"C° 96–85". Seeing "measured" next to a hardcoded 13 and next to "WHO, Codex, Sphere" under a
pack that says those bodies never reviewed it. Being told on one slide that the site exists in
25 languages and in two, and getting a 404 for Japanese. Clicking "Previous" with Enter and
moving forward. Being an investor and finding the one wrong number on the page that promises
counting. Being a food-bank lead and failing at the very first command because the templates it
names are a different format from the tool.

## The one change I would make first

Fix the signature so that `signedAt`, `kid` and `alg` are inside the signed bytes and every
verification path enforces revocation and validity, then ship the vector that fails on a
backdated signature. Everything the site promises about recalls, key revocation, witnessed
checkpoints and verifiable records rests on that one line in `tools/cookwala_ref.py`, and today
it can be defeated with a text editor.
